### 1.3 不可测试/难测试 AC 重点剖析（7 条）

**① AC-201「无违禁词」——🔴 核心负断言问题**

| 问题 | 说明 | 改进建议 |
|:--|:--|:--|
| 判定源未定稿 | 「无违禁词」依据哪个词库？M1 compliance.py + toolgood_words + medical 规则包的**版本与词表快照**未锁定；词库变更即断言漂移 | 合规服务发布时锁定词库版本（如 medical_rules_v1.0 + toolgood_words_2026Q3），测试按版本快照断言 |
| 负断言不可穷举 | 词库零命中 ≠ 语义合规（如「效果立竿见影」绕过词库）；LLM 兜底修正质量不可机器断言 | 定义两级口径：**机器判定**（词库+规则包零命中，可自动化）为 AC 验收标准；**语义抽检**（LLM-judge/人工）为 P1 补充 |
| 修正动作不可观测 | 「经合规修正后」需留痕才能断言 | 复用 DDL 已有字段 `message.compliance_passed`，落库 fixes[] 修正记录，断言 compliance_passed=1 或修正记录非空 |
| 采样规则未定义 | E2E 提示词条数/二级行业覆盖未定义 | 定稿抽样集：5 二级行业 × 每行业 ≥3 组医美文案提示词（含已知违禁注入） |
| 「行业话术」主观 | 无法断言「体现医美行业话术」 | 转客观：断言回复 artifact.metadata.cited_banks 命中 informate-industry_医美（见②） |

**② AC-202「命中行业知识」——🟡 命中不可观测**

检索命中（P1→P4 哪个 bank/哪条条目）在**对话回复路径无落库点**：Schema 的 `cited_banks` 仅定义在产出物 metadata 上，DDL message 表无检索命中字段，测试无法断言「命中行业叠加层而非纯通用」。改进：① message 表或独立 retrieval_log 增加 `cited_entries`（命中 bank_id + 条目 ID，每次检索落库）；② AC-202 断言改为「回复消息的 cited_entries 含 informate-industry_医美 条目」；③ AC-203 断言改为「P1/P2 条目 ID 出现在 cited_entries 且先于 P3/P4」——**把优先级语义变成顺序可观测**。

**③ AC-205「轮次计费边界」——🟡 off-by-one 未定稿**

| 模糊点 | 现状 | 需定稿内容 |
|:--|:--|:--|
| 计数起点 | turns 从 0 还是 1？round_no 与 turns 的换算关系 | 定义 turns = 已完成回复轮数，首轮发起后 turns=1；测试用例表按 turns 逐值断言 |
| 提示时机 | 「第 20 轮末」= 第 20 轮回复流式结束追加提示条（round_complete 事件）？还是第 21 轮发送前？UIUX 两处提示（20 轮末系统提示条 + 21 轮起输入框轻提示）可能重叠 | 事件契约 `round_hint.type` 与 UI 呈现一一映射：`included_used`（turns=20 回复结束）/ `extra_round`（turns≥21 发送前）/ `limit_50`（turns=50 回复结束）/ `low_balance` |
| 51 轮拦截判定 | 技术方案「turns ≥ 50 → 拦截」：turns=50（50 轮已完成）时发第 51 条被拦 | 明确：拦截发生在发送第 51 条消息时（turns=50），且**不冻结不扣费**；补 50 轮全量计费边界用例（10+30×1=**40 积分上限**，AC 未覆盖） |
| 文案歧义 | UIUX §2.3「第 50 轮末提示『已用满含轮』」——50 轮早已超含轮，此处应提示上限而非含轮 | 文案模板修正，提示变量与轮次阈值绑定（pricing.included_rounds / round_limit 渲染） |
| 冻结口径 | 「turns ≥ 20 → 增量冻结 1」与「第 21 轮起每轮扣 1」是否等价（20 轮完成时发第 21 条才冻结） | 边界表定稿：turns=19/20/21/49/50/51 六点 ×（冻结/扣减/提示/拦截）四断言 |

**④ AC-403「Agent 基于元数据继续工作」——🟡 语义断言**

可自动化的部分：传递后目标会话创建、首条注入消息含 Payload 摘要（prompt/风格/受众/卖点）、artifact.source_artifact_id 关联、审计记录；「目标 Agent 基于元数据继续工作」的语义质量不可自动化。改进：AC 断言收窄为 **Payload 注入可观测**（目标会话消息 + artifact.metadata_payload 字段完整性断言），语义质量作 P1 人工/LLM-judge 抽检。

**⑤ AC-502「水印固定样式」——🟡 视觉断言**

图片文件内合成水印的「固定样式」无法用 API 断言。改进：① 代码级断言——水印合成函数单测（位置/文案/不透明度参数化）+ 生成文件元数据（ai_label/trial_watermark 字段）；② 视觉抽检——固定样例图人工走查一次，回归靠函数断言；③ 像素级自动化（P2）：检测右下角区域非背景像素占比。

**⑥ AC-601「充值到账」——🟡 外部依赖未定**

支付渠道未定（PRD §7.4 开放问题 2；技术方案 R10：对公转账人工确认回调），真实「支付成功→到账」链路含人工环节，无法 E2E 自动化。改进：① 测试路径 = 内部回调接口 `/recharge/callback`（签名校验）模拟支付成功，断言到账公式（金额×10×(1+赠比)）+ 流水 + trial→active 流转；② 三档位（100/500/2000）表驱动断言；③ 「即时到账」量化（建议回调处理后 ≤5s 余额可见）；④ 人工确认环节验证进管理后台用例（T11），在线支付接入后补真实渠道 E2E。

**⑦ AC-706「管理员收到预警」——🟡 预警载体未定义**

PRD/技术方案/UIUX 均提到「超限预警」，但无预警记录表、无接口、audit_log 无约定 action，测试无从断言「收到预警」。改进：① 定义预警落点（建议 audit_log action=`limit_warn` + 员工管理页预警标记 + 后台待办角标）；② DDL 补充约定；③ 限额周期（credit_period='day'）跨天重置需时间注入测试（系统时钟抽象）。

## 5. 维度五：复验结论

### 5.1 结论

**设计门 QA 视角：有条件通过。**

通过的理由（验收体系底子好）：
1. 46 AC 与 46 FR 一一对应、编号可追溯，多数 AC 可直接转化为测试用例；
2. 计费异常对照表（PRD §4.4）是天然回归清单，技术方案还补了迟到回调补偿与 30 分钟自动释放规则；
3. 隔离测试 ISO-01~07 已固化并绑定 Hermes 升级回归，AC-203/207 专项落地；
4. 技术方案明确要求计费/隔离条目必须单元+E2E 双覆盖；
5. 范围声明诚实（CI/CD 非目标、支付渠道未定、开放问题列明），QA 可据此规划 mock 策略。
