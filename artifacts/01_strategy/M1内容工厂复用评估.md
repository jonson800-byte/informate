## 三、关键洞察

### 1. content-factory 的真实媒体接入恰好是 Informate 要做的

M1.0 阶段媒体全是 **mock**（config: `image.provider: mock`、`video.provider: mock`），真实 Seedance/图片供应商接入是 M1.1 未完成工作（media.py 里 `raise MediaError("Seedance 文生视频未接入（M1.1）")`）。

**但对 Informate 是好事**：契约骨架已定义（VolcengineSeedance 客户端、ImageToVideoParams、endpoint 配置预留），直接按成本测算定的分工补齐即可：
- 生图 = Seedream 5.0（0.22 元/张）
- 生视频 = H3 768P / Seedance 720p
- 估算：补齐真实接入约 2-3 人天（契约已有，主要是 API 调用 + 结果校验 + AI 标识）

### 2. 最大可复用资产 = 合规引擎

合规引擎（25.3K + 4 行业规则包 + LLM fallback + 自动修正 diff 回写）是 M1.0 完整交付并通过验收的部分（Codex 确认"安全防御扎实"）。Informate 生图/生视频场景直接需要内容合规（广告法/行业规则），**这一块省 2-3 人天**。

### 3. 架构差异：任务制 vs Chat 制

```
content-factory（任务制）：用户提交表单 → 固定 workflow 编排 → 任务状态机 → 下载
Informate（Chat 制）：    用户对话 → 场景 agent（Hermes profile）→ agent 调用工具 → 产出物展示
```

orchestrator 的"固定 workflow"与"agent 自主决策"冲突，不建议搬。但 agent 工具层（合规检查/生图/生视频）可以直接复用 content-factory 的 services 作为 **agent 可调用的工具函数**。

## 四、复用方案建议（Informate 场景 agent 的工具层）

```
Informate 生图/生视频场景 agent（Hermes profile）
    ↓ 调用工具（复用 content-factory services 改造）
┌─────────────────────────────────────────────┐
│ 工具① 合规检查  ← compliance.py（直接搬）    │
│ 工具② 生图      ← media.generate_image       │
│                  （补 Seedream 5.0 真实接入）  │
│ 工具③ 生视频    ← media.generate_video       │
│                  （补 Seedance/H3 真实接入）  │
│ 工具④ LLM 调用  ← llm.py（直接搬）           │
└─────────────────────────────────────────────┘
```

**实施路径**：
1. 把 compliance.py + 规则包 + llm.py 复制进 Informate 项目（license：灵犀自有代码，无问题）
2. media.py 补真实接入（Seedream/Seedance/H3），沿用其契约
3. auth/quota/store 参考重写为积分扣费 + 租户/会话存储
4. 工具层封装为场景 agent 可调用接口（HTTP 内部 API 或 MCP）

**预估**：复用省 3-5 人天；新增工作量主要在"真实媒体接入补齐 + 积分体系 + Chat 适配"。
