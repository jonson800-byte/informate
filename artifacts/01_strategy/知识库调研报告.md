## 二、Top 3 复用建议

### 🥇 1. RAGFlow（结构复用，最高价值）
- **复用什么**：知识库分层结构（文档 → chunk 切片 → embedding → 检索）与深度文档理解管线（PDF/扫描件解析）
- **复用方式**：结构复用（分层设计）+ 部分代码复用（文档解析管线）
- **license**：Apache-2.0，可商用
- **匹配点**：Informate 0 阶段要手工补入行业知识（术语/FAQ/话术/SOP，大量来自 PDF/文档），RAGFlow 的文档解析链可直接借鉴
- **注意**：RAGFlow 是完整应用（Python/FastAPI/Postgres/ES），不建议整体引入（与 Hermes 生态冲突），只借鉴知识管理分层

### 🥈 2. MaxKB / WeKnora（模式复用，轻量）
- **复用什么**：MaxKB（知识库问答的一体化产品形态）和 WeKnora（RAG + Wiki 自动维护）的产品模式
- **复用方式**：模式复用——"知识库管理界面 + 检索 API"的交互范式，可作为 Informate 知识库模块的产品参考
- **license**：MaxKB GPL-3.0（注意传染性，不抄代码）；WeKnora 待确认
- **匹配点**：Informate 需要"知识库管理"（运营后台维护知识）+"知识注入"（agent 检索）两端

### 🥉 3. mem0（模式复用，知识飞轮核心参考）
- **复用什么**：记忆提取模式——从对话/使用记录中提取结构化记忆、去重、聚合、更新
- **复用方式**：模式复用（提取→去重→更新→检索的记忆生命周期）
- **license**：Apache-2.0
- **匹配点**：Informate 知识飞轮（租户×场景记忆 → 聚合脚本 → 行业知识库）与 mem0 的记忆管理生命周期高度一致；但 Informate 已有 Hindsight（基于 Postgres 的语义记忆库，支持 bank 隔离），**不需要引入 mem0**，只参考其提取/去重策略

## 三、建议自研的部分

| 部分 | 原因 |
|:--|:--|
| **知识库分层结构**（租户知识层 / 行业共享层 / 通用层） | 与 Hindsight bank 体系（租户 bank + 行业 bank + 通用 bank）天然对应，自研很轻 |

## 四、对 Informate 知识库结构设计的建议

基于调研，Informate 知识库建议采用**三层结构 + 两种存储**：

```
┌─────────────────────────────────────────────┐
│ ① 通用知识层（平台级）                        │
│   通用 FAQ / 通用话术 / 通用 SOP              │
│   Hindsight: informate-common bank           │
├─────────────────────────────────────────────┤
│ ② 行业知识层（行业共享，脱敏后沉淀）           │
│   行业术语 / 行业FAQ / 行业话术 / 法规库       │
│   Hindsight: informate-industry_<行业> bank  │
│   ← 知识飞轮聚合脚本写入（灵犀逻辑延续）       │
├─────────────────────────────────────────────┤
│ ③ 租户知识层（租户私有）                      │
│   客户业务知识 / 私有资料 / 专属话术           │
│   Hindsight: informate-tenant_<租户> bank    │
│   ← 只写自己的 bank（facts_boundary 思路）    │
└─────────────────────────────────────────────┘
```

**两种存储**：
- **结构化知识**（术语/FAQ/话术/SOP）：Postgres 表 + 语义检索（Hindsight），管理界面参考 MaxKB 的产品形态
- **文档知识**（PDF/扫描件，0 阶段手工录入）：文档解析管线参考 RAGFlow（chunk → embedding），解析后入 Hindsight

**接口建议**：
- `POST /knowledge/import`（文档导入：PDF/Word → 解析 → 入库）
- `POST /knowledge/query`（RAG 检索：场景 agent 调用，传 tenant_id + industry + query）
- `POST /knowledge/aggregate`（聚合脚本触发：租户 bank → 脱敏 → 行业 bank）

## 五、明确结论

1. **不引入重型平台**（Dify/RAGFlow/FastGPT 都不装）——Informate 的知识库底座是 **Hindsight bank 体系**，天然支持三层隔离
2. **借鉴结构**：RAGFlow 的知识管理分层、MaxKB 的管理界面形态、mem0 的记忆提取生命周期
3. **自研**：知识 schema、聚合脚本（已有灵犀设计参考）、管理 API
4. **0 阶段启动**：手工录入行业知识（术语/FAQ/话术）→ 按三层结构入库 → 场景 agent 通过查询接口使用

> 后续待验证：MaxKB/WeKnora/wanwu 的 license 细节（子代理在 license 验证环节超时，未全部完成）；建议在正式设计前对 Top 2 项目（RAGFlow/MaxKB）做一次深度源码走读（tech-repo-analysis 流程）。
