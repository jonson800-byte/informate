## 1. 产品概述与目标

### 1.1 产品定位

**Informate = 面向企业的 AI 能力平台（场景化 Chat 工作台）。** 企业开通账号、一次性部署场景、充值积分，员工在对话里使用 AI 能力，产出物自动展示，所有能力按积分计费。

- **形态**：三栏 Web 工作台——左栏场景列表、中栏 Chat 主窗口、右栏产出物面板
- **核心主张**：「不用搭的 AI 工作台」——用户只学对话，复杂度全部收进后端（场景 = Agent 配置）
- **差异化**：行业×场景深度知识 + 合规能力（医美内容合规为零号客户强卖点）
- **驱动逻辑**：与灵犀（无 chat、工作流驱动、8 个页面）相反——人对话 → AI 干活 → 产出物展示

### 1.2 目标用户与角色

| 角色 | 说明 | 核心诉求 |
|:--|:--|:--|
| 企业主账号（管理员） | 公司采购/IT/老板 | 开户、部署场景、充值、看用量、管员工、控成本 |
| 员工子账号 | 实际用 AI 干活的员工 | 选场景、对话、拿产出物，无需学习系统 |
| 平台运营（内部） | Informate 团队 | 管理后台：租户/场景/积分/审计/导出，不依赖改数据库 |

### 1.3 产品范围（MVP）

**MVP 场景（2 个）**：
1. **行业工作助手** —— 通用文本对话底座 + 按客户行业加载行业知识叠加层（零号客户实例 = 医美行业工作助手）
2. **生成图片** —— 营销图/海报/产品图（Seedream 5.0，异步任务）

**增购项（MVP 不交付）**：生成视频（H3 标准档 + Seedance 品质档双轨）——成本高/异步复杂，异步队列成熟后接入。
**Phase 2/3 预留**：产出物微调 Canvas（一键重绘/换背景/换比例）、对话式 @引用、企微适配层、知识自动聚合飞轮（v2.0）。

### 1.4 零号客户与打样指标（Q27）

零号客户 = **医美一级行业**，5 个二级行业：植发 / 口腔 / 皮肤 / 整形 / 光电。首个实例 = 「医美行业工作助手」+「医美营销生图」（合规检查为默认能力）。打样期建议 ≥ 4 周，目标值上线前与销售对齐：

| 指标 | 定义 | 建议目标值 | 采集方式 |
|:--|:--|:--|:--|
| 周活率 | 每周至少发起 1 次会话的员工数 ÷ 已开通员工数 | ≥ 60% | 会话审计统计 |
| 任务完成率 | 「完成」会话数 ÷ 付费会话总数（完成判定：用户好评/明确结束语，或产出物被下载/跨场景传递） | ≥ 70% | 会话审计 + 产出物事件埋点 |
| 续费意向 | 打样期结束回访中明确表示续费并考虑增购（如生成视频）的客户占比 | ≥ 80% | 销售回访 + 后台充值数据 |

**体验目标（Q29）**：零号客户员工 **15 分钟培训即可上手**——培训后能独立完成「登录 → 选场景 → 发起会话 → 拿到产出物 → 下载」全流程，无需理解积分/计费细节（计费只在余额不足时介入提示）。

**打样范围与里程碑（建议）**：
| 阶段 | 内容 | 输出 |
|:--|:--|:--|
| 第 1 周 | 医美 5 二级行业种子知识入库 + 场景包配置 + 隔离 SPIKE | 可演示的医美行业工作助手 |
| 第 2 周 | 工作台联调（三栏 + 计费 + 后台） | 内部完整闭环 |
| 第 3 周 | 零号客户试用上线（2-3 家医美机构，每家 ≤ 10 员工） | 试用数据 |
| 第 4 周起 | 打样观察期：周活/完成率/续费意向数据采集 | 打样报告 + 调价/增购建议 |

### 1.5 非目标（MVP 明确不做）

- 不交付生成视频场景（增购项）
- 不做产出物微调 Canvas、对话式 @引用
- 不做企微/IM 嵌入（仅架构预留适配层）
- 不做知识自动聚合飞轮（v2.0；MVP 用 Obsidian 人工种子知识）
- 不正式开放多行业（架构支持，执行只聚焦医美打样）
- 不做积分有效期、效果不满意退款

## 2. 功能需求

**编号规则**：FR-XXY 按模块分段编号——10 段 = 平台基础、20 段 = 行业工作助手、30 段 = 生成图片、40 段 = 产出物面板与跨场景传递、50 段 = 试用引导、60 段 = 充值积分、70 段 = 管理后台。每条 FR 有且仅有一条同号 AC（§6），优先级 P0 = MVP 必须，P1 = 首期建议。

| FR-103 | **场景列表（左栏）**：仅展示该租户已部署且状态为 active 的场景；未部署/暂停场景不出现 | P0 |

### 2.2 行业工作助手（FR-20 段）

| 编号 | 需求条目 | 优先级 |
|:--|:--|:--|

| FR-203 | **二级行业检索**：检索优先级硬编码 P1 租户私有 bank（sub_industry 精确）→ P2 行业 bank 中 sub_industry = 租户二级行业 → P3 行业 bank 通用条目 → P4 通用 bank | P0 |
| FR-204 | **医美合规检查（默认能力）**：输出内容过 M1 合规引擎（medical 规则包：广告法绝对化用语/医疗广告审查/前后对比禁令/违禁词库），命中即自动修正或拦截并提示 | P0 |

| FR-206 | **上下文管理**：历史超长时自动压缩/截断，控制输入 token（Hermes 原生能力） | P1 |
| FR-207 | **租户记忆**：会话记忆写入租户独立 bank，命名由 `bank_id_template: 'informate-tenant-{user}-{profile}'` 解析（`{user}`=租户 ID，仅后端可信注入；`{profile}`=场景名）；同租户不同场景 bank 隔离，进程间不共享 | P0 |
| FR-208 | **会话可用性检查**：会话发起时按状态校验——trial 只查剩余试用次数（不查余额）；active 查余额 ≥ 本次冻结额（会话 10 / 生图 15）；paused/expired 拒绝并发起引导 | P0 |
| FR-209 | **医美文案发布审查提示（合规保护）**：行业工作助手生成营销文案时，自动附带合规提示「需人工审核且取得《医疗广告审查证明》后方可投放」，不向客户承诺"生成即可投放"；后台可配置提示文案 | P0 |

### 2.8 页面信息架构（三栏布局，前端开发依据）

**整体**：单页三栏 Web 应用，1024px 以下降级为「场景列表 → 对话 → 产出物」三步切换（移动端适配不做深度优化，P2）。

| 区域 | 内容 | 交互要点 |
|:--|:--|:--|
| 左栏（场景列表） | 租户已部署场景图标+名称；底部：余额展示（积分）、充值入口、帮助 | 场景切换 = 切换后端能力与对话上下文；当前场景高亮 |
| 中栏（Chat 主窗口） | 消息流（用户/AI 气泡）、输入框、新开对话按钮、合规提示条 | 流式输出；场景切换后保留各场景独立对话历史 |
| 右栏（产出物面板） | 当前对话产出物卡片流 + 「历史产出」标签 | 卡片含：缩略图/类型/时间/下载/重新生成/发送到其他场景 |

**关键状态页**：
- 冻结提示页（租户 paused/expired）：说明原因 + 联系运营入口，无任何功能入口
- 试用额度不足提示：展示剩余次数，引导转正式（充值按钮）
- 50 轮上限提示：引导「新开对话」（按钮直达）

## 3. 用户故事与关键流程

### 3.1 用户故事

- **US-1 医美市场部小张（员工）**：作为医美机构市场人员，我想直接跟「医美行业工作助手」对话要一段植发项目朋友圈文案，它自动用行业话术并规避广告法违禁词——这样我不需要学系统，也不用担心文案违规。
  - 验收条件（Given/When/Then）：Given 租户已部署医美行业工作助手且余额充足；When 小张输入「写一段植发项目朋友圈文案，突出效果好」；Then 回复使用医美行业话术、无「最佳/第一/根治」等违禁词，且会话扣 10 积分（20 轮内）。
- **US-2 医美机构主账号李总（管理员）**：作为老板，我想充值积分并给员工设消费限额，这样我能控制成本、看到每个员工在用什么。
  - 验收条件：Given 李总为主账号；When 李总充值 500 元并给某员工设 100 积分/日限额；Then 员工消费达限额后被拦截，李总在后台看到消费明细与预警。
- **US-3 小张（生图 + 传递）**：作为市场人员，我想描述「夏季促销海报」让 AI 直接出图，满意后把图发送到行业工作助手配文案——这样海报和文案一次搞定，不用切软件。
  - 验收条件：Given 租户已部署生成图片与行业工作助手；When 小张描述海报需求并点「发送到其他场景」选行业工作助手；Then 图片 + 元数据进入目标场景对话，Agent 可基于图片与卖点直接产出文案。
- **US-4 平台运营（内部）**：作为运营，我想在后台给新客户开试用、配置积分单价、查会话审计、导出数据——这样不依赖改数据库就能完成整个生意闭环。
  - 验收条件：Given 运营有后台权限；When 创建医美租户 → 部署场景 → 改生图单价为 18 积分；Then 新生图任务按 18 积分计费，全部操作留审计。

### 3.2 关键流程

**流程 1：开户 → 试用**
销售确认客户 → 运营在后台创建租户（行业=医美，二级=植发等）→ 系统生成主账号凭据 → 主账号登录创建员工子账号 → 客户进入 trial（20 次会话 + 水印生图）→ 首次登录弹 3 步引导 → 员工发出第一条消息。**异常分支**：行业知识叠加层未就绪时，部署被拒并提示运营补齐种子知识。

**流程 2：试用 → 充值 → 正式**
客户试用满意（或在额度用尽提示处）→ 选择充值档位（1 元 = 10 积分，阶梯赠分）→ 支付成功即时到账 → 租户转 active → 水印移除/次数解锁/跨场景传递开放 → 主账号设置员工限额。**分支**：客户未充值但要求退出 → 走数据导出后停用。

**流程 3：使用（行业工作助手会话）**
选场景 → 发消息 → 后端校验（active + 余额 > 0）→ 无状态 Worker 全量注入（角色定义 + 租户 bank + 行业叠加层）→ 知识检索 P1→P4 → 合规检查 → 流式回复 → 计轮（20 轮内含，超轮 1 积分/轮）→ 达 50 轮拦截提示新开对话。**会话结束**：结算扣分，记忆写入租户 bank，会话记录落库可审计。

**流程 4：产出物展示与跨场景传递**
生图任务成功 → 产出物自动进右栏 → 预览/下载，不满意可重新生成（按次计费）→ 满意后点「发送到其他场景」→ 选目标场景 → 文件 + 元数据 Payload 投入目标场景新对话 → 目标 Agent 基于元数据继续工作 → 传递事件进审计日志。**限制**：试用期/目标场景未部署时按钮不可用。

**流程 5：欠费冻结**
余额低于最低冻结额 → 系统检测 → 租户转 paused → 工作台显示冻结提示页（不可发起新会话，历史与数据保留）→ 主账号充值 → 即时恢复 active。**提示**：余额即将不足时（低于 N 次会话额度）提前弹充值提醒，避免使用中断。

**流程 6：后台运营闭环**
创建租户/开试用 → 部署场景挂行业知识 → 配置积分单价 → 监控会话审计与看板 → 到期/违规暂停 → 数据导出 → 续费/增购新场景。

### 3.3 租户状态流转（开发用状态机）

```
trial ──充值/付费──▶ active ──欠费/到期──▶ paused ──充值──▶ active
  │                    │                     │
  │                    ├──到期未续──▶ expired（数据保留 X 天后可清理，需合规评估）
  │                    └──违规/客户要求──▶ paused（人工操作）
  └──试用期结束未付费──▶ expired 或 数据导出后停用
```

| 状态 | 可用性 | 触发条件 | 恢复条件 |
|:--|:--|:--|:--|
| trial | 会话 20 次、生图带水印、禁跨场景传递 | 新租户创建 | 充值/付费 → active |
| active | 全部功能 | 转正式 | — |
| paused | 仅冻结提示页 | 余额不足 / 后台暂停 | 充值 / 后台恢复 |
| expired | 仅冻结提示页（数据导出仍可用） | 到期未续 | 续费重新开通 |

**关键规则**：任何状态下，租户私有数据（会话/产出物/积分流水）不删除（expired 数据清理需单独合规评估，默认保留）；冻结与解冻均为系统自动判定 + 后台人工可干预。

## 4. 计费与积分规则

### 4.1 定价总览（D4 + Q26 定稿口径）

| 项目 | 价格 | 说明 |
|:--|:--|:--|
| 场景部署费 | ¥500/场景/一次性 | 首单免部署费（D3 引流）；覆盖开通配置成本，持续收入靠积分 |
| 积分兑换 | 1 元 = 10 积分 | 充值档位见 FR-601 |
| 行业工作助手 | **10 积分/会话（含 20 轮）** | 超轮 1 积分/轮，单会话上限 50 轮 |
| 生成图片 | **对外 20 积分/张，实际执行 15 积分/张** | 报价保守档 20、建议执行档 15（给客户让利） |
| 生成视频（增购） | 标准档对外 200/实际 150；品质档对外 400/实际 300 | MVP 不交付，价格占位 |

> ⚠️ 所有单价均为管理后台可配置变量（FR-704）；上线前按 DeepSeek 最新官方价重算一次（峰谷翻倍已执行 + 预告大涨）。

### 4.2 会话计费口径（Q26）

- **轮的定义**：1 轮 = 用户发送 1 条消息 + Agent 完成 1 次回复（流式输出结束即算完成；工具调用/思考过程计入该轮，不额外计）。
- **扣费**：会话结算制——20 轮内扣 10 积分；第 21 轮起按 1 积分/轮逐轮续扣。
- **上限**：单会话 50 轮（第 50 轮正常完成并计费），**第 51 轮发送被拦截**并提示「建议新开对话」（新开会话重新计费，防套利）。
- **对外表述**：「10 积分/任务（约 20 轮对话），超量 1 积分/轮」。
- **毛利校验**：20 轮成本 ≈ 0.3-0.4 元 vs 售价 1 元（10 积分）→ 毛利 60-70%；超轮 1 积分/轮 vs 深对话轮成本 0.02-0.1 元 → 盈利。

**计费示例（医美市场部日常）**：
- 小张开 1 个会话写文案，共 18 轮 → 扣 10 积分（1 元）。
- 同一会话聊到 25 轮 → 扣 10 + 5×1 = 15 积分（1.5 元）。
- 生成 3 张海报（执行价 15 积分）→ 每张冻结 15，成功各扣 15，共 45 积分（4.5 元）。
- 其中 1 张上游失败 → 原子解冻 15 积分退回，最终实扣 30 积分。
- 李总充值 100 元（到账 1100 积分，含 100 赠分）→ 上述使用合计 1 元档 1 次 + 45 积分 ≈ 2.5 元/半天工作量，一个充值周期（1100 积分）约覆盖 65-95 个任务。

### 4.3 积分事务状态机（Q20）

**任务级（生图/生视频）**：
```
提交任务 → [冻结] → 上游成功 webhook → [扣减]（终态）
              ↓
     上游失败/取消/超时 → [原子解冻]（终态）
```

**会话级（行业工作助手，逐轮续扣）**：
```
会话首轮发起 → [冻结 10] → 第 20 轮内正常对话（含轮不追加扣费）
  → 第 21 轮起每轮发起前 [增量冻结 1] → 该轮回复完成 [扣减 1]
  → 会话结束/新开对话 → 冻结余额 [结算]（未扣部分解冻）
  → 第 51 轮 → 拦截新消息（不冻结不扣费），提示新开对话
  → 会话中途余额不足（< 1 积分）→ 当前轮允许完成，下一轮前冻结并引导充值
```

- **冻结**：任务/会话提交时冻结预估积分（会话 = 10，生图 = 实际执行价 15）。
- **扣减**：仅明确成功（生图 webhook 成功 / 会话该轮回复完成）后扣减；webhook 幂等，重复回调不重复扣。
- **解冻**：失败/取消/超时原子解冻，原路退回余额。
- **兜底**：冻结超时（webhook 丢失）由后台定时任务扫描解冻。
- **价格口径（M-13 定稿）**：生图对外展示价 20 积分/张（报价/文案），实际扣费 15 积分/张（执行优惠价）——前端与流水统一按此口径，充值赠分同理（100 元 = 1100）。

### 4.4 积分规则明细

| 规则 | 内容 |
|:--|:--|
| 失败退分 | 仅生成失败退分（网络/上游错误/超时）；生成成功但效果不满意不退 |
| 无有效期 | 积分不设过期时间 |
| 欠费冻结 | 余额不足即冻结（paused），停止新会话；充值即时恢复 |
| 积分共享 | 积分为企业池共享，全体员工消费同一池 |
| 员工限额 | 后台可设员工级积分限额，防单员工耗尽全池 |

**计费异常场景对照（开发/QA 必测）**：

| 场景 | 预期行为 |
|:--|:--|
| 生图 webhook 重复回调 | 幂等：只扣一次，不重复扣分 |
| 生图 webhook 丢失/超时 | 后台定时任务扫描冻结超时任务，原子解冻，用户可重试 |
| 会话中余额刚好用尽（第 18 轮余额 0） | 当前回合允许完成，下一回合前冻结并提示充值 |
| 并发提交生图（余额仅够 1 张） | 按提交顺序冻结，余额不足的任务进入失败态并提示 |
| 试用额度与积分余额并存 | 试用 20 次会话额度优先于积分扣减；转正式后按积分计费 |
| 员工限额与租户余额同时不足 | 先判租户余额，再判员工限额，提示语区分原因 |

## 6. 验收标准（AC-xx 与 FR-xx 一一对应）

- **AC-505**：试用结束后可导出自有数据，或转正式继续使用。

### 充值积分（AC-60 段）
- **AC-601**：主账号充值 100 元 → 到账 1100 积分（1000 基础 + 100 赠分，10% 档位），余额即时更新；500 元档到账 6000、2000 元档到账 25000。
- **AC-602**：工作台展示余额与最近消费逐笔记录。
- **AC-603**：消费明细可查：时间/场景/类型/积分/关联产出物或会话 ID。
- **AC-604**：冻结 → 扣减/解冻全流程在积分流水中有记录，失败退分金额正确。
- **AC-605**：余额不足触发冻结，工作台不可发起新会话；充值后 1 分钟内恢复。
- **AC-606**：余额跨月不过期。

### 管理后台（AC-70 段）
- **AC-701**：后台可创建/编辑/暂停/到期租户，一级+二级行业归属可设置。
- **AC-702**：按租户开通/关闭场景；部署时自动关联一级行业知识叠加层。
- **AC-703**：充值记录/余额/冻结解冻流水可查；手动调账（赠送/扣回）留审计。
- **AC-704**：修改会话含轮数（如 20→30）或生图单价后，新会话/新任务按新价计费，改动有记录。
- **AC-705**：会话审计可按租户/员工/场景筛选，显示轮次/token/扣分；审计日志可查可导。
- **AC-706**：员工限额生效：单员工消费达限额后该员工会话被拦截，管理员收到预警。
- **AC-707**：按租户导出数据（会话/产出物/积分流水）成功生成 JSON/CSV 文件。
- **AC-708**：运营看板展示租户数/会话数/生图数/收入/成本统计。
