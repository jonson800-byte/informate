## 0. 文档速览（给开发的 30 秒）

- **一页三栏**：左场景列表（240px）/ 中 Chat 主窗口（自适应）/ 右产出物面板（360px）；1024px 以下降级为「场景列表 → 对话 → 产出物」三步切换（深度移动端适配 P2 不做）。
- **用户只学对话**：所有能力入口 = 左栏选场景 + 中间一个输入框；计费/积分细节只在关键时刻（超轮/欠费/额度用尽）以提示出现，不常驻干扰。
- **三个强制状态页**：试用引导弹窗（员工首次登录）、充值弹窗（主账号/欠费）、冻结提示页（paused/expired 整页替换）。
- **两枚「标识」独立处理**：试用营销水印（仅试用期，转正式后新产出物移除）vs 合规 AI 标识（2026 国标要求，**永久保留**）——两个元素分别渲染、分别由后端写入图片文件，前端不做剥离入口。
- **前端零硬编码**：场景名/单价/含轮数/轮次上限/产出物操作按钮全部由「租户场景列表接口 + 场景包元数据」驱动，交互与场景包 Schema 字段一一对齐（§6）。

## 1. 设计原则

### 1.1 P1 用户只学对话（最高原则）

**来源**：灵犀（Lingxi）失败教训——8 个模块页面、用户要学系统；Informate 相反：**复杂度全部收进后端，前端永远只有一个对话窗口**（v3.1 §1.3）。

| # | 规则 | 实现约束 |
|:--|:--|:--|
| R1 | 主界面永远只有 1 个输入框、1 个发送按钮 | 生图/生视频/未来任何场景都不新增表单，需求全部用自然语言表达 |
| R2 | 切换场景 = 换一个对话环境 | 用户无感后端能力切换；各场景对话历史独立保留（FR-104） |
| R3 | 计费信息默认隐藏，只在关键时刻介入 | 仅 4 个触发点：第 20 轮末 / 第 21 轮起每轮 / 第 50 轮拦截 / 余额不足与欠费（FR-205/605） |
| R4 | 新能力 = 新场景 = 左栏新条目 | 不新增页面、不改交互范式；场景包即能力（Q24） |
| R5 | 工作台常驻按钮 ≤ 12 个 | 超出即违反原则，评审拦截 |

### 1.2 P2 零号客户 15 分钟上手（Q29 体验目标）

**验收口径**（PRD §1.4）：培训后能独立完成「登录 → 选场景 → 发起会话 → 拿到产出物 → 下载」全流程，无需理解积分/计费细节。

落地手段：
1. **首次登录 3 步引导**（FR-503，见 §3.1/§4.4）：选场景 → 发第一条消息 → 看产出物。
2. **空态即教程**：左/中/右三栏空态文案各自引导下一步动作（见 §2 各栏空态）。
3. **常用操作 ≤ 2 次点击可达**：发消息 1 次、下载产出物 2 次（点卡片 → 下载）、新开对话 1 次、充值 2 次（主账号）。
4. **员工视角零配置**：无任何表单/设置项；积分余额只读展示，充值/消费记录/员工管理入口仅主账号可见（FR-105）。

### 1.3 P3 医美客户：专业可信、不浮夸（Q27 零号客户基调）

医美 = 高客单、强监管、广告法敏感 → 视觉与文案基调：**专业、克制、可信**。

| 维度 | 要求 | 反例（禁止） |
|:--|:--|:--|
| 视觉 | 低饱和暖白底 + 沉稳主色（墨绿/驼金，§5.1 两方案） | 霓虹渐变、高饱和撞色、粒子/3D 动效 |
| 文案 | 「助手」「生成」「审阅」等克制词汇；**平台自身文案也过广告法**（不用「最强/颠覆/神器」） | 「AI 魔法」「一键爆款」类营销腔 |
| 合规 | 合规提示条常驻，把合规表现为**专业能力**而非限制（医美内容合规是卖点，Q27） | 弱化/藏匿合规信息 |
| 能力表达 | 用「行业工作助手」称谓（Q28 品牌名），不夸「智能」 | 「超级智能体」等 |

### 1.4 原则检查表（设计与评审通用）

| # | 检查项 | 通过标准 |
|:--|:--|:--|
| C1 | 新员工 15 分钟走通主流程 | 无引导提示下 5 分钟内完成「登录→发消息→看产出物」 |
| C2 | 界面无积分计费常驻元素 | 计费只出现在 §1.1-R3 的 4 个触发点 |
| C3 | 任一页面按钮总数 | 工作台常驻 ≤ 12；弹窗 ≤ 3 个主操作 |
| C4 | 文案合规自查 | 平台界面文案过违禁词库扫描（M1 规则包） |

## 2. 信息架构：三栏布局

### 2.1 整体布局

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏（全页）：Logo · 平台名 · 租户名+行业标签 · 试用/正式徽标 · 用户菜单 │
├──────────┬───────────────────────────────┬───────────────────────┤
│ 左栏 240  │  中栏 Chat（自适应，最小 480）   │ 右栏 360              │
│          │  顶部：场景名 + 新开对话按钮      │  产出物面板           │
│ 场景列表  │  消息流（流式）                 │  [当前对话|历史产出]    │
│          │  合规提示条（常驻）              │  产出物卡片流          │
│ 余额卡    │  输入区（多行输入 + 发送）       │  （预览/下载/传递）     │
│ 充值(主)  │                               │                      │
│ 帮助      │                               │                      │
└──────────┴───────────────────────────────┴───────────────────────┘
```

- **栅格**：左 240px 固定 / 右 360px 固定 / 中自适应（最小 480px）；页面最小宽度 1080px。
- **1024px 以下降级**：三栏 → 三步切换（场景列表页 → 对话页 → 产出物页），各步顶部提供返回与下一步入口；不做深度移动端优化（P2，PRD §2.8）。
- **视觉层级**：中栏为视觉重心（白底、内容密度高）；左右栏次级（浅灰底 `#F7F8FA`）。
- **顶栏**：品牌区（左）+ 租户信息（中：「XX医美 · 医美行业」，展示行业归属增强「自己行业的助手」感知）+ 用户菜单（右：主账号含「员工管理/充值/退出」；员工仅「退出」，FR-105）。**管理后台为平台运营独立入口（admin 账号体系，G3 定稿），不放入租户主账号菜单——运营后台与租户工作台完全分离**...

### 2.2 左栏：场景列表

**内容与优先级（自上而下）**：
1. **场景列表**（唯一导航，最高优先级）
2. **余额卡**（底部固定）：积分余额 + 「充值」按钮 + 「消费记录」入口（**仅主账号可见**；员工只读余额；消费记录=最近逐笔：时间/场景/类型/积分，点击展开下拉，对应 FR-602/AC-602）...
3. **帮助入口**：折叠式「使用帮助/联系运营」（员工遇阻时兜底）

**场景条目设计**：
- **数据来源**：仅展示该租户**已部署且 status=active** 的场景（FR-103，AC-103）——未部署（如生成视频）/暂停场景不出现，前端不做本地过滤，后端返回即渲染。
- **条目结构**：场景图标（24px，来自场景包 `emoji`）+ 显示名 + 可选一行最近会话预览（灰字 12px，无则省略）。
- **品牌名规则（Q28）**：显示名 = 行业前缀 + 场景基名，由场景包 `display_name_template`（含 `{industry}` 占位符）按租户一级行业渲染下发（§6.2），**前端零硬编码**。零号客户实例：
  - 行业工作助手 → **「医美行业工作助手」**
  - 生成图片 → **「医美营销生图」**
- **交互**：单击切换场景（切换 = 后端能力切换 + 该场景独立对话历史恢复，FR-104）；当前场景高亮（主色左侧 3px 竖条 + 浅主色底 `#E8F3F0`）。
- **场景徽标**：生图场景条目可带「异步」小徽标（提示产出物需等待，FR-303 感知前置）。
- **空态**（无已部署场景）：
  - 员工：「暂无可用场景，请联系管理员开通」
  - 主账号：「暂无可用场景，请前往管理后台部署」（按钮直达后台）

### 2.3 中栏：Chat 主窗口

**顶部栏**：场景显示名（如「医美行业工作助手」）+ 状态徽标（试用中/正式，来自租户 status）+ 「新开对话」按钮（图标+文字，FR-104；点击即清空消息流，**不弹确认**——上下文清空可预期，且历史会话后台保留，误操作可新开回看历史产出）。

**消息流**：
- 用户消息右对齐（主色底白字气泡 `#1F6E5C`）；AI 消息左对齐（白底卡片，带「AI」小徽标——合规透明，NFR-01 界面侧）。
- **流式输出**（FR-201）：AI 回复逐 token 渲染，输出中显示光标；完整回复前不可发送下一条（防乱序）；回复结束 = 该轮计费完成（PRD §4.2 轮定义）。
- **冷启动占位**（NFR-13）：热 Worker（池内）首 token ≤ 2s；池外冷启动时 AI 侧显示「正在准备你的行业助手…」占位气泡（≤30s），**不允许空白等待**。
- **轮次提示**（FR-205，AC-205）：
  - **第 20 轮末**：AI 回复结束后，消息流追加系统提示条（非 AI 消息、居中、浅灰底）：「本会话已用满 20 轮含轮额度，之后每轮消耗 1 积分」。
  - **第 21 轮起**：输入框上方出现轻提示（非阻塞、淡入淡出）：「本轮将消耗 1 积分」。
  - **第 50 轮正常完成并计费**（50 轮已是超轮区，**不重复 20 轮「已用满含轮」文案**——50 轮末改为「已达单会话上限，下一轮将无法发送」，与 51 轮拦截提示衔接，G15 定稿）；**第 51 轮发送被拦截**——输入框禁用 + 居中提示条「已达单会话 50 轮上限，建议新开对话」+ 内嵌按钮「新开对话」（直达，PRD §2.8 关键状态页）。
- **余额与冻结提示**（FR-208/605，AC-208）：
  - **发起前校验**：active 租户余额 < 本次冻结额（会话 10 / 生图 15，取场景最小值 10）→ 拒绝发起并弹提示「余额不足，请充值后继续」+ 充值按钮（主账号）/「请联系管理员充值」（员工）。
  - **会话中途余额用尽**（PRD §4.3）：当前轮允许完成，下一轮发起前冻结失败 → 提示「余额不足，本轮完成后将暂停使用，请充值」。
  - **预警**：余额 < 30 积分（约 3 次会话）时，会话结束 toast + 左栏余额卡变琥珀色「余额即将不足，建议充值」（提前介入避免中断，PRD 流程 5）。
- **合规提示条（常驻，FR-209）**：中栏底部细条（浅琥珀底）：「内容生成需人工审核，取得《医疗广告审查证明》后方可投放」——文案后台可配置（FR-704），行业工作助手场景显示，生图场景显示「生成图片不得用于前后对比等医疗效果承诺」。

**输入区**：多行输入框（Enter 发送 / Shift+Enter 换行）+ 发送按钮；禁用态（会话被冻结/50 轮拦截/租户非可用态）；输入示例占位文案：**「向医美行业工作助手描述你的需求，例如：写一段植发项目朋友圈文案」**（场景名与示例来自场景包，§6.2）。

**空态（新开对话后）**：居中引导卡：「向[场景名]描述你的需求」+ 3 个示例问法 chips（点击即发送，示例来自场景包 `suggestions` 字段，见 §6.1 schema）——把「不会用」变成「点一下」。

### 2.4 右栏：产出物面板

**结构**：面板头「产出物」+ 标签切换「**当前对话** | **历史产出**」（FR-401，AC-401）+ 产出物卡片流。

- **当前对话**：默认选中，展示本会话产出物（按时间正序）。
- **历史产出**：本场景全部历史产出（时间倒序，分页加载），含其他会话产出——员工可在新会话继续取用历史成果（FR-104 联动）。
- **面板折叠**：可折叠为窄条（右栏 360→48px），折叠后新产出物到达时顶栏徽标闪烁提示（不打扰原则的例外：产出物是任务结果，须可见）。

**产出物卡片（type 驱动模板，§6.3 契约）**：

| 类型 | 卡片内容 | 操作组（由 `artifact.actions` 渲染，§6.2） |
|:--|:--|:--|
| image | 缩略图（3:4 裁切，点击全屏预览）+ 时间 + 状态 | 预览 / 下载原图 / 重新生成 / 发送到其他场景（FR-402/403） |
| text | 首行标题截断 + 类型图标 + 时间 | 复制 / 下载 / 发送到其他场景（FR-402） |
| 未知 type | 通用文件卡（图标+文件名） | 下载（降级不报错，§6.3） |

- **生成中卡片**（FR-303，AC-302）：骨架占位 + 任务状态徽标流转「排队中 → 生成中 → 成功/失败」；生图为异步 Job，**不阻塞对话**（NFR-15）。
- **失败卡片**（FR-304，AC-304）：红色状态 + 失败原因 + 「重试」按钮；积分已原子解冻（余额可见变化，AC-604）。
- **重新生成**：按次计费，点击前轻提示「重新生成将消耗 [生图单价] 积分」（费用文案来自 pricing 配置，开放问题待定，UI 按计费实现）。
- **跨场景传递**（FR-403/404，AC-403/404）：
  - 按钮「发送到其他场景」→ 弹出轻量选择器（**目标场景列表 = 已部署的其他 active 场景**，来自后端接口；未部署不出现在选择器）。
  - **试用期：按钮隐藏**（FR-404「隐藏或置灰」取隐藏——与试用限制矩阵「禁用跨场景传递」表述一致，且避免员工困惑）。
  - 确认后 toast：「已发送至 [目标场景] 新对话」；目标场景自动新建会话，首条消息为注入的系统说明「来自 [来源场景] 的产出物」+ 元数据摘要（prompt/风格标签/受众/卖点，Q23 Payload），目标 Agent 基于元数据继续工作（AC-403）。
  - 传递事件写入审计日志（FR-405，AC-405）。
- **合规提示（界面侧）**：图片卡片右下角显示「AI 生成」小徽标（正式）/「含试用水印」小徽标（试用期）——仅提示性展示，**真正的标识/水印渲染在图片文件内**（后端合成，§5.4/§5.5；NFR-01）。
- **空态**：「对话中生成的图片、文本会自动出现在这里」+ 指向中栏输入区。

### 2.5 全局状态与提示规范

| 形态 | 规格 | 用途 |
|:--|:--|:--|
| toast | 右上滑入，3s 自动消失，可堆叠 | 发送成功/扣分/传递成功/预警 |
| 系统提示条 | 居中浅灰条，非 AI 消息 | 20 轮末/50 轮拦截/余额不足 |
| 弹窗 | 居中卡片 + 遮罩，Esc 关闭，可点遮罩关闭 | 充值/试用引导/传递选择器 |
| 整页状态 | 居中卡片，无功能入口 | 冻结提示页（FR-106） |
| 加载/骨架 | 灰底微光动画 | 列表/卡片加载、冷启动占位 |

## 3. 关键流程

### 3.1 开户 → 试用引导（3 步）（FR-101/501/503，PRD 流程 1）

```
运营后台创建租户(行业=医美, 二级=植发等) → 生成主账号凭据 → 交付客户
  → 主账号首次登录（不弹引导，先建员工子账号）
  → 员工首次登录 → 弹 3 步引导 → 发出第一条消息 → 进入试用体验
```

**3 步引导内容**（FR-503，形态见 §4.4）：
1. **第 1 步「选场景」**：左栏高亮引导——「从左侧选择你要用的场景，每个场景是一个专属助手」。
2. **第 2 步「发消息」**：箭头指向输入框——「像聊天一样描述需求，例如：写一段植发项目朋友圈文案」。
3. **第 3 步「看产出物」**：指向右栏——「AI 生成的图片/文本会自动出现在右侧，可下载或发送到其他场景」。

展示规则：**仅员工子账号首次登录展示一次**（后端 seen 标记，重登不再弹）；可跳过（右上角「跳过，直接开始」）；主账号不展示（管理视角）。trial 状态顶栏持续展示「试用中 · 剩余 N 次会话」轻提示（FR-106，不遮功能）。

### 3.2 试用 → 充值（阶梯包）→ 转正式（FR-601/504/505，PRD 流程 2）

**充值触发时机**：a) 主账号点左栏余额卡「充值」；b) 试用额度用尽提示处（第 21 次会话发起被拦 → 「试用次数已用完」+ 充值按钮）；c) 余额不足拦截处；d) 冻结提示页「立即充值」。

**充值弹窗档位**（FR-601，AC-601，阶梯包金额与赠比后台可配 FR-704）：

| 档位 | 实付 | 到账积分 | 赠比 | 角标 |
|:--|:--|:--|:--|:--|
| 1 | 100 元 | 1100 | 赠 10% | — |
| 2 | 500 元 | 6000 | 赠 20% | 最受欢迎（推荐） |
| 3 | 2000 元 | 25000 | 赠 25% | 最高性价比 |

- 弹窗说明：「1 元 = 10 积分 · 积分长期有效 · 全公司员工共享」（FR-606 无有效期 + 企业池共享）。
- 支付成功 → **即时到账**（余额动画刷新 + 成功 toast + 消费记录出现，FR-601/603，AC-601）。

**转正式（trial → active）**，充值/付费成功后一次性生效（FR-504，AC-504）：
1. **试用营销水印**：**新产出物不再带**；**存量产出物保持原样**（历史文件不可追溯改写，右栏历史产出中试用期文件保留「试用期生成」小标注，界面透明说明）。
2. **次数解锁**：会话次数限制解除，改走积分计费。
3. **跨场景传递开放**：「发送到其他场景」按钮出现。
4. **合规 AI 标识：永久保留**（与试用水印独立处理，见 §3.4）。
5. 顶栏「试用中」徽标移除；余额卡恢复正常状态。

**退出分支**（FR-505）：试用结束未付费 → 主账号用户菜单「数据导出」→ 导出自有数据（会话/产出物/流水，FR-707/NFR-10）→ 停用。

### 3.3 欠费冻结 → 恢复（FR-605/106，PRD 流程 5）

```
余额 < 30 积分（预警）→ 余额 < 10（冻结触发值）→ 系统转 paused
  → 工作台整页替换为冻结提示页（不可发起新会话，历史数据保留）
  → 主账号在冻结页点「立即充值」→ 支付成功 → 即时恢复 active → 回到工作台
```

- **预警阈值**：余额 < 30 积分（约 3 次会话额度），每次会话结束 toast + 左栏余额卡变琥珀（提前介入避免使用中断，PRD 流程 5 要求）。
- **冻结触发**：余额 < 最低冻结额（会话 10 / 生图 15，取场景最小值 **10**，FR-605）→ 系统自动转 paused。
- **员工视角**：冻结页提示「请联系管理员充值」（员工无充值入口，FR-105）。
- **恢复**：充值后 **1 分钟内恢复** active（AC-605）；恢复后回到原工作台，历史会话/产出物完整（FR-605「历史数据保留」）。
- **trial 租户不受欠费冻结影响**：trial 走次数额度，余额为 0 仍可发起会话（FR-208/605，AC-208）。

### 3.4 试用水印 vs 合规 AI 标识（两个独立元素，FR-504 + NFR-01）

| 元素 | 性质 | 样式（§5.4 详述） | 生命周期 |
|:--|:--|:--|:--|
| 试用营销水印 | 营销限制（试用限制矩阵，v3.1 §4.1） | 「Informate 试用版」横排 + 45° 细斜纹底纹，右下角，半透明 | **仅试用期**；转正式后**新产出物移除**（存量保留原样） |
| 合规 AI 标识 | 法律合规（2026 生成式 AI 国标 + 清朗专项行动红线，NFR-01） | 「AI 生成」白底小标签 + 国标标识图形 + 元数据写入文件 | **永久保留**（试用+正式，不随状态变化） |

实现约束：**两个元素分别渲染、分别由后端在生成图片时合成进文件**（前端无剥离/关闭入口）；位置避免重叠（AI 标识更小，位于水印上方 12px 或对角）。转正式逻辑只关停「试用水印」通道，AI 标识通道恒定（AC-504 断言：水印消失但 AI 标识仍存在）。

## 5. 视觉方向

### 5.1 基调与可选方案

**关键词**：专业、可信、干净、克制。参考气质：医疗/金融 SaaS（丁香园后台、挂号网、飞书），**不是**消费娱乐产品。

**两个暖色调方案（提交零号客户选择，选定后统一设计 token）**：

| | A 方案「暖白·沉稳」（推荐） | B 方案「暖金·亲和」 |
|:--|:--|:--|
| 主色 | 深墨绿 `#1F6E5C`（专业 + 医疗联想） | 驼金 `#A67B3D`（商务暖感） |
| 辅助 | 浅绿 `#E8F3F0`、琥珀 `#C98A3D` | 浅驼 `#F3EAD9`、棕 `#6B4F2A` |
| 背景 | 暖白 `#FAFAF7` + 白 | 暖白 `#FBF7EF` + 白 |
| 适用 | 医美/医疗行业主推 | 商务/美容连锁备选 |

**动效规范**：仅保留必要过渡——页面切换淡入 150ms、流式打字、toast 滑入 200ms、弹窗遮罩淡入 150ms；**禁用**弹跳/3D/粒子/大面积位移动效。

**圆角**：卡片 8px、按钮 6px、气泡 10px、弹窗 12px（克制圆角，非「大圆角可爱风」）。

- 行高 1.6；中文正文不用斜体；强调用色不用粗体堆砌。

### 5.4 水印样式（后端合成进图片文件，前端只展示示意）

**试用营销水印**：
- 位置：图片右下角；内容：「Informate 试用版」横排文字（系统无衬线，字号 = 图片宽度 × 4%，最小 14px）+ 45° 细斜纹底纹（间距 24px，不透明度 8%）覆盖右下 1/4 区域。
- 整体不透明度 ~35%（可见但不过度破坏内容）；与 AI 标识不重叠（见下）。

**合规 AI 标识（NFR-01）**：
- 位置：右下角最底（或与水印对角——取对角：AI 标识左下、试用水印右下，避免重叠）；内容：「AI 生成」白底 60% 圆角小标签（字号固定 12px，深灰字 `#374151`）+ 国标「AI」标识图形。
- 元数据：图片写入 AI 生成元数据（PNG tEXt / JPEG XMP，C2PA 兼容留口），符合 2026 生成式 AI 国标。

**前端职责**：右栏卡片角标（「AI 生成」/「含试用水印」）仅为缩略图提示；**不提供任何去水印/去标识操作**；下载原图 = 后端原文件（含合成标识）。

### 5.5 AI 标识的界面呈现（透明性，NFR-01/05）

1. **图片产出物**：右下角「AI 生成」角标（§5.4）。
2. **文本产出物**：内容末尾附一行小字（12px 灰）「本内容由 AI 生成，需人工审核后使用」（行业工作助手场景自动附带，FR-209 合规提示）。
3. **对话内**：AI 消息头像旁「AI」小徽标。
4. **登录页/关于**：平台备案信息 + 「本平台 AI 生成内容均带标识」声明。
5. **试用 vs 正式**：两元素独立（§3.4），转正式只移除试用水印，AI 标识恒定。

| 轮次提示文案（20 轮/1 积分/50 轮） | `pricing.included_rounds` / `extra_round_points` / `round_limit` | 文案 = 模板 + 变量，如「已用满 {included_rounds} 轮含轮额度…」 |
| 产出物卡片操作组 | **`artifact.actions[]`**：`{label, type(download/copy/regenerate/send_to_scenario), target_scenario}` | 按钮由后端 Payload 驱动（Gemini Payload 契约，PRD 附录）；未知 type 降级通用文件卡 |
| 跨场景传递选择器 | `artifact.actions[].target_scenario` | 仅渲染后端允许的目标；试用期整体隐藏（租户 status 驱动） |
| 重新生成 | tool `seedream_v5_generator` JSON Schema（prompt/negative_prompt/aspect_ratio/…） | 复用 `artifact.metadata.seedream_params` 重新提交 |
| 卡片元数据展示/传递 | `artifact.metadata`（prompt/style_tags/target_product/受众/卖点） | 传递时随文件投递（Q23 Payload） |
| 任务状态徽标 | 任务实体 `status`（queued/processing/success/failed） | 生图异步 Job 可见（FR-303） |
| 记忆写入 | `memory.bank_id_template`（informate-tenant-{user}-{profile}）+ Hindsight 埋点 | 用户点赞/满意时写租户 bank（Phase2 细化） |
| 试用限制（水印/次数/禁传递） | 平台配置 + 租户 `status=trial`（非场景包字段） | 前端由租户状态驱动，不做本地推断 |

### 6.3 前端契约要求（开发约束）

1. **不硬编码**场景名/单价/轮数/按钮：全部从「租户场景列表接口」（返回已部署 active 场景 + 元数据）+「场景包元数据接口」渲染。
2. **产出物卡片 = artifact 对象直接渲染**：`type` 决定模板，`actions` 决定按钮；未知 type 降级为通用文件卡，不报错。
3. **跨场景传递** = 调 `POST /artifacts/{id}/transfer`，前端仅传 `target_scenario_id`；审计由后端完成（FR-405）。
4. **状态徽标**（试用/正式/冻结）来自租户 `status` 字段，前端不推断。
5. **价格文案**统一从 `pricing` 配置渲染，后台调价（FR-704）后前端提示自动跟随，无需发版。
