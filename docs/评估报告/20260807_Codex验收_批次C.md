### 🔴 高（5 项）

**H1｜输出侧合规缺失（合规红线能力未闭环）**
- 文件：[chat.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/chat.ts:147>)（仅 147-155 行检查输入）、[chat.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/chat.ts:254>)（assistant 消息无条件写 `compliance_passed=1`）

**H2｜生图前置合规缺失（FR-306/307、AC-306/307）**
- 文件：[imagegen.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/imagegen.ts:150>)（execute 路由无任何合规调用）、[credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/credit.ts:303>)（冻结发生在任务创建时）

- 修复：在冻结前（T5 创建端点）或 execute 入队前做 prompt 合规检查；被拦截时不入队并原子 release 已冻结分，返回拦截原因。

**H3｜失败重试二次失败后冻结分永久卡死（资金损失）**
- 文件：[credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/credit.ts:330>)（`release` 只要有任意 `unfreeze` 流水即 `refunded:0` 重放）、[imagegen.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/imagegen.ts:191>)（重试用新幂等键再冻结 15）
- 问题：首次失败已产生 unfreeze 流水 → 重试再冻结（freeze #2）→ 重试再失败时 `release` 判定「已解冻」直接跳过，freeze #2 永不退回；`scanExpiredFreezes`（credit.ts:495-503）同样走 `release`，30 分钟兜底也救不回。用户净损失 15 积分/次。T7.3 只测了「重试→成功」，未覆盖「重试→再失败」。
- 修复：`release` 按 ref 计算未终结冻结余额（Σfreeze − Σunfreeze − Σsettle）并原子退回差额，或改为按冻结流水逐笔解冻。

**H4｜内存队列 close() 死锁，优雅关闭挂起**
- 文件：[taskQueue.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/taskQueue.ts:126>)（close 置 closed 后 await drain）、[taskQueue.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/taskQueue.ts:92>)（pump 见 closed 即不再消费队列）
- 问题：`close()` 后仍排队的任务永远不会被 pump 消费，`drain()` 的 waiter 永不 resolve → `app.close()`（imagegen.ts:145 onClose 钩子）永久挂起，SIGTERM 无法退出。测试恰好都在任务终态后关闭，掩盖了该问题。
- 修复：close 时消费完剩余任务再置 closed，或清空队列并对每个 pending 任务走失败退分后 resolve 所有 drain waiter。

**H5｜SSE 无 raw error 监听 + Hermes 真实模式无超时**
- 文件：[chat.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/chat.ts:201>)（send 仅 try/catch 同步写异常，`reply.raw` 的 `error` 事件无人监听）、[hermesClient.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/hermesClient.ts:71>)（real 模式 fetch/reader 无超时，AbortController 只由客户端 close 触发）
- 问题：客户端在写入中途断开时 `reply.raw` 可能触发未捕获的 `error`（ECONNRESET）导致进程崩溃；Hermes 上游挂起时 SSE 连接无限期占用，无首包/空闲超时兜底。
- 修复：`reply.raw.on('error', ...)` 与 `request.raw.on('error')` 统一吞掉并中止生成；给 Hermes 流加首包超时（如 40s 冷启动上限）与总时长/空闲超时；SSE 可加心跳注释行防代理超时。
