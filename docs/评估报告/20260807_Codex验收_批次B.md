## 问题清单

### 高

**H1. JWT 默认密钥硬编码，可伪造 admin token**
[config.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/config.ts:8>) 第 8 行：`jwtSecret: process.env.JWT_SECRET ?? 'informate-dev-secret-change-me'`。密钥写死在仓库内，生产未配置环境变量时，任何人可用已知密钥签发 `{role:'admin', tenantId:null}` 的 token，直接接管调账/调价/导出等全部管理接口；[auth.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/middleware/auth.ts:37>) `jwt.verify` 也未固定 `algorithms`。修复：生产环境缺 `JWT_SECRET` 直接拒绝启动；`verify` 显式指定 `algorithms:['HS256']`。

**H2. 员工限额（FR-706/AC-706，P0）完全未落地**
[credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/credit.ts:244>) `createFreeze` 只校验租户余额，[credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/credit.ts:86>) 会话创建与生图冻结入口均不校验 `user.credit_limit`。实测 `credit_limit=0` 的员工可正常创建会话。技术方案 T5 验收标准 ⑥ 明确要求“员工限额拦截+预警”，PRD §4.4 要求“先判租户余额，再判员工限额”。修复：会话/轮次/生图冻结前按周期限额判定，超限返回区分原因并带预警字段。

**H3. 迁移 002 在存量库上必然失败（发布阻断）**
[002_scenario_package.sql](</Users/zhangyihui/Desktop/Informate Project/backend/src/db/migrations/002_scenario_package.sql:44>) 直接 `DROP TABLE scenario_deployment`。`createDb` 开启 `foreign_keys=ON`，一旦 `conversation.deployment_id` 有引用行，DROP 的隐式 DELETE 触发 FK 约束失败。已用内存库实测：含会话数据的库执行 002 报 `FOREIGN KEY constraint failed`。修复：重建表前在事务内临时关闭 FK 并校验无孤儿引用，或改为增量 `ALTER TABLE`；补“存量库升级”测试用例。

**H4. 合规引擎“行业领先”自修复死循环 → 合规文案被误拦截**
[rule_packs.py](</Users/zhangyihui/Desktop/Informate Project/services/compliance/rule_packs.py:93>) 将“行业领先”列入虚假数据 patterns，而 [rule_packs.py](</Users/zhangyihui/Desktop/Informate Project/services/compliance/rule_packs.py:124>) FIXES 将其映射为自身（身份映射）。实测“我们是行业领先”“行业领先机构”均被 3 轮修正后强制 blocked；且“行业第一”的合规替代表述恰是“行业领先”，修正后反被拦截，直接破坏 fix-and-recheck 核心流程（FR-204/AC-204）。修复：删除身份映射或加“替换无变化即停止/不拦截”的防停滞判定，并补回归用例。

**H5. 会话基础费缺少正式结算记录，账本/看板/导出失真**
[credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/services/credit.ts:364>) `settleConversation` 对已用会话只插入 `amount=0` 的 settle 流水，base 10 无 settle 也无 unfreeze；[admin_credit.ts](</Users/zhangyihui/Desktop/Informate Project/backend/src/routes/admin_credit.ts:46>) 的 `frozen_outstanding`（freeze−settle−unfreeze）与 `total_consumed`（Σsettle）据此聚合。实测：每个已结算会话在途冻结永久残留 +10，总消耗少计 10/会话；部署费（记作 adjust 负值）同样不计入消耗。修复：按实际应收写 `settle amount=base(+超轮)`，或看板按 `conversation.billing_state` 与冻结流水联动统计。

### 中

**M1. 会话创建不校验场景 `pricing_unit`/部署归属；幂等重放产生幻影行**
