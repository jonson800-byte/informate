## 验收结论

**有条件通过** —— 文档方向、45 FR↔45 AC 配对、计费与试用基线大体一致，SPIKE 核心机制结论与源码吻合；但存在试用/欠费状态机自相矛盾、充值赠分金额三处口径冲突、`bank_id_template` 缺场景维度且与 PRD 命名不一致、合规水印双重语义、KB 内部红线冲突等必须修复项，修复前不建议直接进入第二批开发，修复后可进入场景包 Schema + UI/UX 阶段。

补充核对：PRD 计 FR-101~106（6）+201~208（8）+301~307（7）+401~405（5）+501~505（5）+601~606（6）+701~708（8）= **45 条，与 45 条 AC 严格同号配对**。SPIKE 引用的 `bank_id_template` schema 行（实际 1072 行）、运行时解析（1534-1536）、解析函数（644-670）、`HINDSIGHT_BANK_ID` fallback（399 行）、`config_schema.py` 仅注册 `bank_id` 未注册 `bank_id_template`，均与源码一致。

## 必须修复的前 5 项

1. **试用/欠费/余额校验状态机统一（H-01 + H-02）**：明确 trial 不受 active 校验与余额检查限制、冻结提示页仅限 paused/expired、"余额<最低冻结额→paused"的精确阈值，并补对应 AC——这是当前文档里最直接的逻辑矛盾，开发照做必然返工。
2. **计费口径单一事实来源（H-03 + H-07 + M-13）**：统一充值赠分金额（100 元=1100）、生图展示价与扣费价、会话逐轮续扣的冻结/结算状态机，并为 18/25 轮、赠分、余额中途用尽补 AC 断言。
3. **`bank_id_template` 定稿并落地场景维度（H-04 + M-16）**：确认模板必须含场景占位符（`informate-tenant-{user}-{profile}` 或等价方案），明确 {user}=租户 ID、由后端可信注入；将"api_server 无 user_id 通道"升级为 P0 集成阻塞项，作为第二批第一个技术实验。
4. **合规水印语义拆分 + 文案发布审查机制（H-05 + H-06）**：区分试用营销水印与合规 AI 标识（转正式后 AI 标识永久保留），并补"医美文案生成后需人工审核/审查证明方可投放"的产品约束与提示，避免"不用担心违规"卖点反噬。
5. **种子知识红线一致性修复（H-08 + M-19 + M-20）**：改写"无痕"等与合规红线冲突的术语、补齐缺失红线（治愈率/变相广告/贬低同行）与案例来源、补足皮肤/整形/光电及 SOP/案例/模板量级。

结论重申：第一批交付物总体可信、SPIKE 机制结论经源码核实正确，但在上述 5 项修复完成前不建议启动第二批开发；修复后可进入"场景包 Schema（memory 段落地 bank_id_template）+ UI/UX 交互设计"。
