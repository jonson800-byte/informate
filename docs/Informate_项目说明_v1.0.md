## 1. 项目概述

**Informate = 面向企业的 AI 能力平台（B端 AI 赋能平台）。**

- **形态**：Web 页面，三栏布局——左侧场景列表 / 中间 Chat 主窗口 / 右侧产出物面板
- **本质**：Chat 驱动的多 Agent 聚合页面。企业开通账号、充值积分，在对话里使用 AI 能力，产出物自动展示，所有能力按积分计费
- **一句话**：让企业花小钱用上 AI，按场景对话干活，用多少扣多少积分

### 1.1 与灵犀（Lingxi）的关系

| 维度 | 灵犀（已冻结） | Informate（主产品） |
|:--|:--|:--|
| 驱动方式 | 无 chat，完全由工作流推进 | **Chat 驱动** |
| 交互 | web 页面复杂（8 模块） | 多 Agent 聚合页，场景化优化 |
| 状态 | 暂时冻结（是否解冻看需求） | 独立运行，独立目录 |
| 资产 | 仅参考逻辑与背景知识 | 拆件复用（见 §7） |

## 2. 产品设计（Q1-Q17 决策）

### 2.1 场景体系

- **MVP 场景**（Q2）：工作助手、生成图片、生成视频
- **后续场景**：数据分析、投放和线索跟进、金牌销售、智能客服等（按市场热度逐个开放）
- **场景 = 通用 agent 底座 + 行业知识层**（二维矩阵：场景 × 行业）；核心洞察源自灵犀："角色包是跨行业的，行业知识只需薄薄一层"
- **场景开放**（Q4）：需开通费，后端按"每租户每场景"配置独立 agent

### 2.2 前端交互（Q5/Q6/Q7）

- **三栏布局**：左 = 场景列表（按客户开通开放）；中 = Chat 主窗口；右 = 产出物面板
- **产出物**：默认显示当前对话产出，可切换历史产出标签；**手动跨场景传递**（Q5）——点击"发送到其他场景"→ 投入对应场景对话（如做图成品 → 投放场景引用）
- **会话**（Q6）：场景下可新开对话，新开清空上下文，后台保留历史记录

### 2.3 租户与账号（Q3/Q15）

- **每租户每场景独立 agent**（C 混合路线：先独立验证，后规模化演进）
- **核心目的**：通过独立 agent 收集不同行业在场景下的共性需求 → 后期变更为**行业垂直场景 agent**（有行业知识和沉淀的 agent 比通用 agent 更有价值）
- **租户信息模型**（延用灵犀客户注册表格式）：id / 公司名称 / 行业 / 子行业 / 状态 / 方案 / 联系人 / 到期时间 / 数据隔离边界；**补充字段**：企业规模、业务类型、目标市场
- **每 agent 独立记忆/知识库**，便于后期汇总收集整理

### 2.4 账号体系（Q6 建议）

- 企业主账号（管充值/开通）+ 员工子账号（管使用）；积分企业池共享；场景下多会话，历史归员工可见、企业可审计

## 3. 商业模式（Q4/Q9/Q14）

### 3.1 计费模型

- **开通费**：¥500 / 场景 / **年**（按年收取）
- **积分充值**：1 元 = 10 积分；按**场景单价**扣费（不按 token）
- **积分规则**（Q9）：失败任务退积分（仅生成失败；效果不满意不退）；暂不设有效期；**欠费冻结**

### 3.2 定价表（Q14，成本占售价 30% 口径）

**报价策略：对外报价保守档，实际执行建议档（给客户让利打折）**

| 场景 | 计价单位 | 模型成本 | 对外报价（保守档） | 实际执行（建议档） |
|:--|:--|:--|:--|:--|
| 工作助手 | 1 会话（≈5轮） | 0.075 元 | 5 积分 | 4 积分 |
| 生成图片 | 1 张 | 0.22 元 | 15 积分 | 10 积分 |
| 生成视频标准档 | 1 条 5s（H3 768P） | 2.50 元 | 160 积分 | 120 积分 |
| 生成视频品质档 | 1 条 5s（Seedance 720p） | 4.97 元 | 330 积分 | 250 积分 |

### 3.3 模型分工（Q11）

- 文本：deepseek-v4-flash
- 生图：火山方舟 **Seedream 5.0**（0.22 元/张）
- 生视频：MiniMax **H3** 768P（标准档，0.50 元/秒）+ 火山方舟 **Seedance 2.0** 720p（品质档，≈1 元/秒）双轨
- ⚠️ 风险：DeepSeek 峰谷 2 倍价待生效（保守档已覆盖）；H3 免费档并发仅 2 任务；Seedance 含视频输入有最低 token 限制

## 4. 知识体系（Q13/Q16/Q17）

### 4.1 知识沉淀飞轮（Q13，延用灵犀设计之初方案）

```
客户使用 → 租户×场景 agent 记忆沉淀（Hindsight）
    ↓ 聚合脚本（提取→去重→脱敏）
写入行业知识库 → 反馈进对应行业 agent（同行业客户共享）
```

- **数据所有权**：客户业务数据归客户；脱敏后的行业知识（术语/场景/模板）归平台
- **两阶段**：第一阶段低价跑数据（积累行业知识）→ 第二阶段提价变现（搭载行业知识库的高级版）

### 4.2 知识库三层结构（Q16）

| 层 | Hindsight bank | 内容 |
|:--|:--|:--|
| 通用层 | informate-common | 平台级 FAQ/话术/SOP |
| 行业层 | informate-industry_<行业> | 行业术语/FAQ/话术/法规库（飞轮写入，脱敏） |
| 租户层 | informate-tenant_<租户> | 租户私有（facts_boundary 隔离） |

**调研结论**：不引入重型平台（Dify/RAGFlow/FastGPT 都不装），底座 = Hindsight bank；借鉴 RAGFlow 文档解析分层、MaxKB 管理界面、mem0 记忆提取生命周期；自研知识 schema + 聚合脚本 + 管理 API。

### 4.3 Obsidian 双重积累（Q17）

- **Obsidian = 人工知识资产层**（`~/Desktop/Informate KB/`，git 管理），Hindsight = 机器记忆层
- **双向同步**：Hindsight 聚合 → flywheel/ 待审阅草稿 → 人工审阅编辑 → industries/ 权威版 → 回灌 Hindsight 行业 bank
- **三角色**：知识飞轮人工质检站 / 行业知识资产库 / 交付物来源
- **红线**：租户私有数据绝不进 Obsidian

## 5. 技术架构方向（Q10）

```
客户浏览器（三栏 Web 页）
    ↓
自建 Node.js API 服务（服务端 Pipeline，2026-06-16 已验证端到端联通）
    ↓ 场景路由（每租户每场景独立 agent）
Hermes profile 引擎（模型 + 角色 + skill + 工作流 + 知识库）
    ↓ 工具层（复用 M1 资产改造）
合规检查 / 生图（Seedream）/ 生视频（H3/Seedance）/ LLM 调用
    ↓
Hindsight 记忆（租户/行业/通用 bank）+ Obsidian 人工层
```
