## Q1 产品关系 — 灵犀冻结，Informate 独立

- **决策**：灵犀产品暂时冻结，Informate 独立运行（本项目目录），两者不同方向
- **灵犀** = 无 chat、完全由工作流推进的产品，web 交互页面复杂
- **Informate** = chat 驱动的产品，本质是多 agent 聚合页面，按客户需求场景化优化
- 两个项目文件各自独立；灵犀是否解冻看后续需求

## Q2 MVP 场景组合

- **决策**：先完成 3 个场景：**工作助手、生成图片、生成视频**
- 后续场景（数据分析、投放和线索跟进、金牌销售、智能客服等）按市场热度逐个开放

## Q3 Agent 架构 — 每租户每场景独立 agent（C 混合路线）

- **决策**：采用 C 混合路线（先独立 agent 验证，后规模化演进）
- **核心目的**：通过独立 agent 收集不同行业在场景下的共性需求，便于后期变更为**行业垂直场景 agent**——有行业知识和沉淀的 agent 比通用 agent 更有价值
- **租户信息**：需收集公司名称、所属行业、企业规模、业务类型、目标市场等
- **独立记忆**：每个独立 agent 建立各自对应的独立记忆/知识库，方便后期汇总收集整理

## Q4 计费模型

- **决策**：开通费为**每场景一次性部署费 ¥500**（一次性收取，非按年）+ 积分充值
- 积分充值按**场景单价**（不是 token 单价）
- 充值比例：**1 元 = 10 积分**
- 需测算不同模型的使用成本（见 Q14）

## Q5 产出物跨场景传递 — 手动方式

- **决策**：用户手动点击"发送到其他场景"→ 产出物直接投放到对应场景的对话中
- 例：做图场景确认满意的图片 → 发送到投放场景使用

## Q6 会话管理

- **决策**：场景下可新开对话，新开对话**清空上下文**，但**后台保留对话记录**

## Q7 右侧产出物面板

- **决策**：默认显示当前对话的产出物，可切换"历史产出"标签页

## Q8 知识库初始化

- **决策**：0 阶段手工补入行业/业务知识（行业术语、FAQ、话术模板、SOP）

## Q9 积分规则

- **决策**：失败任务退积分（**失败 = 生成失败**；生成效果不满意**不退**）

- **欠费冻结**（停止服务）

## Q13 行业知识沉淀飞轮

- **决策**：延用灵犀设计之初的知识沉淀飞轮逻辑（讨论纪要 2.5/2.6/3.1/3.2 节）
- **链路**：客户使用 → 租户×场景 agent 记忆沉淀 → 聚合脚本（提取→去重→脱敏）→ 写入行业知识库 → 反馈进对应行业 agent
- **数据所有权**：客户业务数据归客户；脱敏后的行业知识（术语/场景/模板）归平台
- **两阶段**：第一阶段低价跑数据（积累行业知识），第二阶段提价变现（搭载行业知识库的高级版）
- **沉淀单元**：从灵犀的"客户 bank"细化为"**租户 × 场景** 的独立 agent 记忆"
- **聚合维度**：从"行业"升级为"**行业 × 场景**"

## Q14 成本测算与积分定价

- **决策**：期望毛利率中实际 token 成本占 **30%**（售价 = 成本 ÷ 30%）
- **定价档位**（2026-08-06 确认）：**对外报价用保守档，实际执行建议档**（给客户让利打折）
- **最终定价**（1 元 = 10 积分）：

| 场景 | 计价单位 | 成本 | 对外报价（保守档） | 实际执行（建议档） |
|:--|:--|:--|:--|:--|
| 工作助手 | 1 会话（≈5轮） | 0.075 元 | 5 积分 | 4 积分 |
| 生成图片 | 1 张（Seedream 5.0） | 0.22 元 | 15 积分 | 10 积分 |
| 生成视频标准档 | 1 条 5s（H3 768P） | 2.50 元 | 160 积分 | 120 积分 |
| 生成视频品质档 | 1 条 5s（Seedance 720p） | 4.97 元 | 330 积分 | 250 积分 |

- **模型分工**：文本 = deepseek-v4-flash；生图 = **Seedream 5.0**（重要发现：Seedance/H3 均不支持生图，补充同平台模型）；生视频 = H3 标准档 + Seedance 品质档双轨
- **风险**：DeepSeek 峰谷 2x 待生效（保守档覆盖）、H3 免费档并发仅 2 任务
- 测算报告：`artifacts/01_strategy/成本测算报告_20260806.md`

## 第二轮决策（2026-08-06 · 5 份评估报告汇总后）

> 评估报告来源：Gemini 可行性 / ChatGPT 建议 / DeepSeek V1 / DeepSeek V2 / Gemini 落地版（均存档于 docs/评估报告/）
> 决策方式：D1-D5 战略分歧由用户拍板（按建议执行）；Q18-Q24 为采纳共识点的新增决策

### D1 客户定位：定位不绑定行业，执行先聚焦

- **定位不变**：面向所有企业客户（不绑定行业，保持平台化架构）
- **执行聚焦**：用"零号客户"打样（首选有业务背景的垂直场景，如电商），跑通"对话→沉淀→增强"闭环后向其他行业复制
- 依据：4/5 报告建议聚焦行业；Gemini 落地版"自己的业务痛点是最好的试金石"

### D2 MVP 范围：视频降级为增购项

- **MVP 主推**：工作助手 + 生成图片（2 个场景）
- **生成视频**：降级为首批付费客户增购项（成本高/异步复杂/失败率高/需求低频），异步队列成熟后接入
- 修正 Q2（原 3 场景 MVP）

### D3 开通费：首单免费引流，正式收费保留

- **正式定价不变**：¥500/场景/**一次性部署费** + 积分消耗（2026-08-06 修正：原"按年"改为一次性；部署费覆盖开通配置成本，持续收入靠积分消耗）
- **新增引流策略**：首单免开通费 / 试用期免费（如注册赠体验积分，功能受限：生图带水印/会话次数限制），降低获客阻力
- 修正 Q4（原无免费引流设计）

### D4 定价上调：按 DeepSeek 涨价预警重算

- **依据**：DeepSeek 已执行峰谷翻倍（高峰 Flash 输出 4 元/M）+ 预告整体大幅上调 → 原定价可能成本倒挂
- **原则**："宁可定价偏高再给折扣，也不要定价过低导致亏损"（B 端客户对价格敏感度低于对好不好用的敏感度）
- **新定价建议表**（对外保守档 / 实际执行档）：

| 场景 | 原对外报价 | 新对外报价（保守） | 新实际执行（建议） |
|:--|:--|:--|:--|
| 工作助手 | 5 积分/会话 | **10 积分/会话** | **8 积分/会话** |
| 生成图片 | 15 积分/张 | **20 积分/张** | **15 积分/张** |
| 生成视频标准档（H3 768P 5s） | 160 积分/条 | **200 积分/条** | **150 积分/条** |
| 生成视频品质档（Seedance 720p 5s） | 330 积分/条 | **400 积分/条** | **300 积分/条** |

- ⚠️ 上线前需按 DeepSeek 最新官方价重算一次（涨幅未量化）；成本模型见 artifacts/01_strategy/成本测算报告_20260806.md

### D5 知识飞轮启动：人工知识先行，自动聚合后置

- **MVP 阶段**：只做租户层记忆（每个 agent 的对话历史与上下文）
- **行业层/通用层**：靠 Obsidian **人工种子知识**（3 个重点行业各 50 术语 + 20 FAQ + 3 话术模板，MVP 前整理入库）
- **聚合脚本（自动飞轮）**：放到 v2.0（有真实业务数据后再自动化）
- 修正 Q13/Q16（原设计自动聚合优先）

### Q25 二级行业概念（2026-08-06 补充）

- **决策**：行业体系采用**两级结构**——一级行业（医美/装修建材/律师/教培/跨境电商…）+ 二级行业（医美→植发/口腔/皮肤/整形/光电…）
- **bank 粒度 = 一级行业**：`informate-industry_医美`（bank 数量可控，不碎片化）
- **知识条目粒度 = 二级行业**：metadata 带 `sub_industry` 字段（植发/口腔/通用），知识 schema 增加该字段
- **检索逻辑**：租户(行业=医美, 二级=植发) → 先取 `sub_industry=植发` 条目，再取行业通用条目（`sub_industry=通用/空`），按权重合并
- **知识飞轮**：聚合脚本沉淀的知识必须标记二级行业，避免不同二级行业的经验混淆
- **垂类 agent 孵化**：垂类粒度可到"医美-植发工作助手"（二级），比一级行业更精准
- **租户模型**：`sub_industry` 字段启用（灵犀客户注册表已有该字段设计）
- **Obsidian 结构**：`industries/医美/` 下按二级行业建子目录（植发/口腔/…）+ 通用/（一级行业通用知识）

### Q26 会话计费口径（2026-08-06 用户确认）

- **轮的定义**：1 轮 = 用户发送一条消息 + Agent 完成一次回复（流式输出结束即算完成；工具调用/思考过程计入该轮，不额外计）
- **工作助手计费**：**1 会话 = 10 积分，含 20 轮**；超出部分 **1 积分/轮自动续扣**
- **计费单位规则（设计门 G2 定稿）**：会话冻结按 `pricing.unit` 区分——**unit=session 场景**（行业工作助手）创建会话冻结 10；**unit=image 场景**（生成图片）**不冻结会话费**（仅任务冻结 15/张），避免"会话 10 + 生图 15"双重扣费；生图场景会话计入试用 20 次额度（FR-501 按会话计）
- **冷启动 SLA（设计门 G5 定稿）**：热 Worker ≤2s；池外冷启动 ≤**40s**（实测 20-40s），前端占位「正在准备」——NFR-13 统一 40s，废弃 30s 表述
- **安全机制**：
  - 单会话轮次上限 **50 轮**，触发后提示"建议新开对话"（新开清上下文，成本重新计算）
  - 上下文管理：历史超长时自动压缩/截断，控制输入 token（Hermes 原生支持）
- **成本校验**：20 轮平均成本 ≈ 0.3-0.4 元，售价 1 元（10 积分）→ **毛利 60-70%** ✅；超轮 1 积分/轮 vs 深对话轮成本 0.02-0.1 元 → 盈利 ✅
- **客户感知**：对外表述"10 积分/任务（约 20 轮对话）"，超量 1 积分/轮
- 替代原"8 积分/会话（不限轮）"（有套利风险）；生图/生视频按次计费不受影响

### Q27 零号客户行业：医美（2026-08-06 用户确认）

### Q28 场景改名：行业工作助手（2026-08-06 用户确认）

### Q30 记忆层架构：Node.js 后端直管 Hindsight API（2026-08-06 用户确认）

- **决策**：Informate 的记忆读写**不由 Hermes Hindsight provider 管理**，由 **Node.js 后端直接调 Hindsight REST API（9177）按租户指定 bank_id**（写入 POST /v1/default/banks/{bank_id}/memories + 检索 recall 注入 prompt）
- **背景**：T2 调试发现 Hermes provider 的 bank 配置读取存在隐蔽时序问题（provider 初始化时 get_hermes_home 疑似返回 default → 全部写入 hermes bank，bank_id_template 不生效）；方案 A（改 Hermes 源码修 provider 配置）成本高、每轮更新要重打
- **理由**：后端本来就知道租户上下文（X-Hermes-User-Id 由它注入），按租户 bank 读写记忆是最自然的设计；与"租户×场景独立记忆"产品需求直接对齐；T5 积分管线的 credit 服务可扩展记忆读写层
- **代价与处理**：
  - Hermes agent 的自动 retain 仍写默认 hermes bank（无业务影响，关闭或忽略）
  - 后端需自建记忆读写层（~1-2 人天，并入 T6）：检索注入 prompt + 显式写入，bank 路由 = `informate-tenant-{tenant}-{scenario}`（租户私有）+ `informate-industry_{industry}`（行业只读）
  - **种子知识入库（T12 后半）直接走此通道**：入库脚本调 Hindsight API 写入 `informate-industry_医美`（带 sub_industry 标记）
- **遗留**：api_server X-Hermes-User-Id 源码改造（T1）**保留**（会话连续性/agent 身份仍有用），但记忆隔离不依赖它
