## 2. Opt-in 客户许可条款草案（NFR-02）

### 2.1 条款草案（可并入服务协议「数据处理与知识共享」节）

> 目的：客户授权才进行业知识聚合（NFR-02），未授权客户数据仅用于其自身服务（NFR-05）。

**TC-01 知识共享计划（自愿加入）**
客户可自愿加入「行业知识共享计划」。加入后，平台可将客户使用过程中产生的**行业问答内容**（不含客户名称、联系人、商业秘密及任何可识别客户主体的信息，先经脱敏处理）聚合入行业知识库（industry bank），用于提升同行业客户的应答质量。加入计划不改变客户数据在未授权场景下的使用边界。

**TC-02 优惠对价**
作为加入知识共享计划的对价，加入客户享积分折扣（折扣比例由平台后台配置，调整时平台提前公示；当前默认折扣以平台公示为准）。

**TC-03 数据用途声明（未加入客户）**
未加入知识共享计划的客户，其输入数据仅用于该客户自身服务（会话、生图、计费、合规审查），平台不以任何形式用于模型训练、行业聚合或其他客户的服务。

**TC-04 退出机制**
客户可随时在工作台「设置 → 知识共享」关闭开关退出计划。退出后新产生的数据不再进入聚合流程；退出前已进入人工审核流程（Draft 状态）的条目不再入库，已入库条目按运营流程下线（NFR-03 强制人工审核：未经人工批准严禁回灌行业 bank）。

**TC-05 明示确认**
注册/开户流程默认不勾选加入知识共享计划（Opt-in 语义，须客户显式勾选确认）。

## 3. 部署费收付流程（FR-606 映射）

### 3.1 定价口径

- 部署费：**¥500 / 场景 / 一次性**（PRD 定价表）；**首单免部署费**（D3 引流，技术方案 §1.4）。
- 与积分的关系：部署费为一次性服务费，**不产生积分**；积分余额无有效期（FR-606），两者互不折算、互不影响。

### 3.2 收付流程（正式商用后启用）

```
商务确认 → 对公转账 → 财务人工确认到账 → 运营后台登记开通 → 开票 → 审计留痕
```

1. **商务确认**：销售/运营与客户确认场景数量与合同（含开票信息：抬头、税号、发票类型普票/专票按客户资质）。
2. **收款**：客户对公转账至公司账户（转账附言约定格式「部署费-客户名-场景数」）；MVP 不支持在线支付。
3. **人工确认**：财务核对银行流水确认到账，在运营后台登记（金额、客户、发票抬头、经办人），写入审计日志。
4. **开通**：运营将客户租户转为 `active`（FR-504：付费后移除试用水印、次数解锁、跨场景传递开放）——部署费与充值均为转 active 的付费条件。
5. **开票**：确认到账后 7 个工作日内开具增值税发票（普票/专票按客户资质）。
6. **留痕**：`audit_log` 记录操作人、IP、时间（NFR 审计要求）。

### 3.3 现状与过渡（MVP 试点期）

- 代码现状：`trial → active` 仅由充值触发（`credit.recharge`，技术方案 §1.4 已注明「MVP 阶段免收，trial→active 仅由充值触发」）。
- 试点期：部署费**免收**，不阻塞试点；本流程定稿存档，作为正式收费的收付/开票/转 active 判定依据（T15 要求「含收付/发票/转 active 判定」）。
- 正式启用条件：对公收款渠道 + 财务登记流程就绪后，由运营后台提供「部署费开通」操作（调账/开通能力，与 FR-703 后台调账同类）。

### 3.4 FR-606 映射

| 事项 | 结论 |
|:--|:--|
| 积分有效期 | 无有效期（FR-606），余额长期有效 |
| 部署费与积分关系 | 独立计收，不折算、不互相抵扣 |
| 退费场景 | 未开通前客户取消 → 全额退款（人工对公退回，审计留痕） |

## 4. DeepSeek 定价重算（P1-7）

### 4.1 重算方法

**积分价值锚定**（按主流充值档保守取值）：

```
1 积分 ≈ 100 元 ÷ 1100 积分 ≈ 0.0909 元
（500=6000 → 0.0833 元/积分；2000=25000 → 0.08 元/积分；取 100 元档为保守锚定）
```

**工作助手单会话成本模型**：

```
单会话成本 = 输入 tokens × P_in + 输出 tokens × P_out
  P_in / P_out：DeepSeek 官方每百万 token 单价（元 / 1M tokens）
单会话收入 = 10 积分 × 0.0909 ≈ 0.91 元（含 20 轮；超轮 1 积分/轮，50 轮上限）
毛利率 = 1 − 单会话成本 / 单会话收入
```

**毛利目标**：T15 验收口径「单价与成本模型一致（毛利 60-70%）」→ 即**成本占比 ≤ 30-40%**（成本/收入 ≤ 0.3 时毛利 ≥ 70%，≤ 0.4 时毛利 ≥ 60%）。

**生图**：执行价 15 积分（对外展示 20，M-13 口径）≈ 1.36 元/张；真实接入后按 Seedream 单价另行复核（P0-3 未接入，试点期不产生真实生图成本）。

### 4.2 参数表（上线前核价项）

| 参数 | 符号 | 取值 | 来源/说明 |
|:--|:--|:--|:--|
| 输入单价 | P_in | **上线前以 DeepSeek 官方定价页核价**（本报告示例假设：2.0 元/1M tokens） | DeepSeek 官网定价页，T15 核价动作 |
| 输出单价 | P_out | 同上（示例假设：8.0 元/1M tokens） | 同上 |
| 单会话输入量 | — | 约 4K tokens（知识检索上下文 + 行业叠加层，T12 种子知识量级估算） | 压测/成本监控校准（NFR-18） |
| 单会话输出量 | — | 约 1.5K tokens（20 轮均值） | 同上 |
| 积分锚定 | — | 100 元 = 1100 积分 | 现有充值档 |

### 4.3 重算结果（示例计算）

示例假设（P_in=2.0，P_out=8.0 元/1M tokens）：

```
单会话成本 = 4,000 × 2.0/1,000,000 + 1,500 × 8.0/1,000,000
           = 0.008 + 0.012 = 0.02 元
单会话收入 = 0.91 元
毛利率     = 1 − 0.02 / 0.91 ≈ 97.8%  ≫ 60-70% 目标
成本占比   = 2.2%  ≤ 30-40% 红线
```

**敏感性（DeepSeek 涨价 10 倍）**：P_in=20、P_out=80 → 单会话成本 0.2 元，毛利 ≈ 78%，仍满足目标。

**触发调价阈值**：单会话成本 ≥ 0.27 元（= 收入 0.91 元 × 30%，毛利 70% 临界）→ 触发调价流程（§4.5 调价示例 SQL）。

### 4.4 结论

1. **现行定价维持**：工作助手 10 积分/会话（含 20 轮）、超轮 1 积分/轮、生图实扣 15 积分，按示例参数毛利 ≈ 97.8%，**满足毛利 60-70% 目标且余量充足**（模型 token 成本仅为直接变动成本；整体定价还需覆盖合规审查、客服等运营成本，由商务定价统筹）。
2. **落参**：将现行价显式写入 `price_config`（§4.5 SQL），使调价可配、可留痕（FR-704）——弥补 seed 不写 `price_config` 的缺口。
3. **监控与触发**：NFR-18 成本监控按场景统计 token 成本；单会话成本触及 0.27 元阈值 → 按 §4.5 调价 SQL 更新，`effective_at=now` 即时生效。
