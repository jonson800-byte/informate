## 1. 项目背景与缘起

### 1.1 市场观察

企业正在经历"AI 焦虑"——知道 AI 重要，但不知道怎么落地。市场现状存在结构性矛盾：

| 现状 | 问题 |
|:--|:--|
| 通用大模型（ChatGPT/DeepSeek 等） | 不接业务场景，员工用几天就不用了 |
| 大型定制 AI 方案 | 几十万起、周期长，大部分企业用不起 |
| 企业实际需要 | 不是 AI 技术，而是「能干活、懂行业、用得上」的 AI 助手 |

企业 AI 投入接受度集中在 ¥3,000-¥30,000/年，且大多无自研技术团队，需要开箱即用。

**2026 年竞争格局**（DeepSeek 评估情报）：大厂全面入局通用办公 Agent——腾讯 WorkBuddy（月活 2097 万，市占 53.8%）、字节豆包专业版、阿里千问办公、金山灵犀、OpenAI ChatGPT Work。**通用办公 Agent 已成红海**，差异化必须靠"行业×场景深度知识"。

### 1.2 灵犀的教训（为什么冻结）

前一产品**灵犀（Lingxi）**走了"无 chat、完全由工作流推进"的路线（8 个模块页面），**最终结论：使用页面和使用逻辑过于复杂**。用户要学 8 个模块，每个模块有自己的表单/流程/状态——对没有技术背景的企业员工学习成本过高。

### 1.3 Informate 的诞生

核心反思：**企业员工已经会聊天，不需要学系统。**

> **把复杂度收进后端，前端永远只有一个对话窗口。**

- **灵犀逻辑**：人操作流程 → 流程调工具（用户学系统）
- **Informate 逻辑**：人对话 → AI 干活 → 产出物展示（用户只学对话）

本质上是**多 Agent 的聚合页面**——每个"场景"背后是一个独立的 AI agent，但用户看到的只是"选一个场景，开始对话"。

## 2. 产品定位

### 2.1 一句话定义

> **Informate = 面向企业的 AI 能力平台。企业开通账号、一次性部署场景、充值积分，在对话里使用 AI 能力，产出物自动展示，所有能力按积分计费。**

### 2.2 产品形态（三栏布局）

```
┌────────────┬──────────────────────────┬─────────────────┐
│  左侧       │  中间                    │  右侧            │
│  场景列表   │  Chat 主窗口             │  产出物面板      │
│            │                          │                  │
│ 工作助手    │  用户: 帮我做一张          │  [图片预览]      │
│ 生成图片    │  夏季促销海报             │   ↓ 下载/发送    │
│ (按客户部署)│  AI: 好的，已生成          │                  │
└────────────┴──────────────────────────┴─────────────────┘
```

### 2.3 与灵犀的差异

| 维度 | 灵犀（冻结） | Informate（主产品） |
|:--|:--|:--|
| 驱动 | 无 chat，工作流驱动 | **Chat 驱动** |
| 前端 | 8 模块页面，用户学系统 | 1 个对话窗口，选场景即用 |
| 复杂度位置 | 前端（用户承担） | **后端（场景=agent 配置）** |
| 计费 | ¥1,000/角色一次性 | **¥500/场景一次性部署费 + 积分消耗** |
| 可扩展性 | 模块堆叠 | 场景按需部署 |

### 2.4 目标客户与执行策略（D1）

- **定位**：面向所有企业客户（不绑定行业，保持平台化架构）
- **执行**：**先聚焦**——零号客户 = **医美行业**（Q27，2026-08-06 确认），跑通"对话→沉淀→增强"闭环后向其他行业复制
- **医美优势**：M1 合规引擎 medical 规则包现成覆盖（广告法/医疗广告审查）、已有客户接触基础、内容合规是强卖点

## 3. 产品设计

### 3.1 前端交互（Q5/Q6/Q7 + Q21/Q22/Q23 补充）

| 决策项 | 决策 |
|:--|:--|
| 产出物面板 | 默认当前对话产出，可切历史标签（Q7） |
| 跨场景传递 | **手动**点击"发送到其他场景"→ 投入对应场景对话（Q5）；**传递带元数据 Payload**（prompt/风格标签/受众/卖点，Q23） |
| 会话管理 | 场景下可新开对话（清上下文），后台保留历史（Q6） |
| 产出物微调 | **Phase 2/3**：右侧面板升级为轻量化微调控制台（一键重绘/换背景/换比例），微调透传结构化参数不走完整 LLM 对话（Q21） |
| 企微适配 | **预留**：前端视图与后端 Agent 引擎解耦，适配器层后期支持嵌入企微办公流（Q22） |

### 3.2 场景体系（Q2 + D2）

**MVP 场景（2 个）**：
1. **行业工作助手** —— 通用文本对话底座 + **按客户行业叠加行业知识**（Q28；零号客户实例 = 医美行业工作助手）
2. **生成图片** —— 营销图/海报/产品图（Seedream 5.0）

**增购项**：生成视频（H3/Seedance）——成本高/异步复杂/失败率高，异步队列成熟后接入

**后续场景**（按市场热度逐个开放）：数据分析、投放和线索跟进、金牌销售、智能客服、内容运营等。

**场景开放逻辑**：客户按需求部署场景（¥500/场景一次性），部署后该场景出现在左侧列表。场景不是平台全给，是按客户需求部署——既卖场景，也让客户界面天然简洁。

### 3.3 场景包定义（Q24）

```
场景包 =
  角色定义（frontmatter + 人设/使命/规则/交付物/流程/风格/指标）  ← 参考 agency-agents-zh
  + Hermes profile 运行时配置（模型/工具/skill/工作流/记忆）
  + 场景专属参数（积分单价 / 产出物类型 / 知识库绑定 / 工作流）
```

**参考实现**：Gemini 落地版给出的"商品图生成"profile 设计（`scenarios/generate_image.yaml`：pricing 积分单价 + refund_on_failure + runtime 模型 + skills + memory_bank 绑定；JSON 工具契约；结构化产出 Payload；Hindsight 记忆埋点）作为场景包 schema 的起点。

### 3.4 Agent 架构：按需拉起 + 记忆独立（Q3 + Q18）

**核心决策（Q18）**：profile **不常驻内存**——配置与记忆持久化在 Hindsight/DB，用户发起对话时动态拉起 Agent 实例，**闲置 15 分钟自动销毁**（Hydration）。

**两种实现**：
- **无状态 Worker + 每次全量注入**（推荐 MVP，Codex 评审采纳）：预启动 N 个场景模板 worker，请求时**全量注入**租户上下文（bank + system prompt），用完**清空状态**（模型会话缓存/工具状态/连接凭据全部重置）——隔离最高，杜绝跨租户污染
- 按需启动 profile（隔离彻底，冷启动延迟）：高价值租户可升级

**Hermes 隔离 SPIKE（评审采纳，设计阶段第一项技术验证）**：写任何架构代码前，验证 Hermes 是否支持多租户注入/生命周期销毁/状态重置，定义 worker 状态重置协议 + 跨租户隔离测试用例。

**保留（Q3 核心动机不变）**：租户×场景**独立记忆/知识库**——每租户×场景一个 Hindsight bank（`informate-tenant_<租户>_<场景>`），进程可共享，记忆必须隔离。行业共性收集靠"记忆独立"实现，不依赖"进程独立"。

**规模控制**：进程池大小按**并发会话**建模（非租户数——1 租户 20 员工×2 场景即可撑爆小池），初期 5-10 并发会话；明确"闲置 15 分钟销毁"语义 = 销毁**租户绑定**（进程回池复用），非销毁进程。

### 3.5 租户与账号（Q15 + Q25）

**租户信息模型**：
```
id / 公司名称 / 一级行业(industry) / 二级行业(sub_industry) / 状态(active/trial/paused/expired)
方案 / 已部署场景(roles) / 联系人 / 创建时间 / 到期时间
补充：企业规模 / 业务类型 / 目标市场
数据隔离边界（facts_boundary）：只读行业知识库，只写自己的租户 bank
```

**二级行业（Q25）**：行业体系两级结构——一级行业（医美/装修建材/律师/教培/跨境电商）+ 二级行业（医美→植发/口腔/皮肤/整形/光电）。bank 粒度 = 一级行业；知识条目粒度 = 二级行业（metadata.sub_industry）。

**账号体系**：企业主账号（管充值/部署）+ 员工子账号（管使用）；积分企业池共享；会话历史归员工可见、企业可审计。

## 4. 商业模式

### 4.1 计费模型（Q4 修正 + D3）

```
客户 → 部署场景（¥500/场景/一次性部署费）→ 充值积分（1元=10积分）→ 使用扣积分 → 用完再充
```

- **部署费**：¥500/场景/**一次性**（覆盖开通配置成本：agent 配置/初始知识库/培训）；持续收入靠积分消耗
- **引流策略（D3）**：首单免部署费 / 试用期免费（注册赠体验积分，功能受限：生图带水印/会话次数限制）
- **试用限制矩阵（评审采纳，量化）**：
  - 生图带水印 → 水印位置/样式固定（右下角）
  - 会话次数限制 → **初期 20 次/租户**
  - 跨场景传递 → **试用期禁用**
  - 试用期结束 → 转正式（付费）或数据导出/清理
- **积分按场景单价扣费**（不按 token）——B 端客户能理解"一张图 20 积分"，不能理解 token
- **积分规则（Q9）**：生成失败退积分（仅生成失败；效果不满意不退）；暂不设有效期；欠费冻结
- **积分单价可配置（评审采纳）**：积分单价为**管理后台可配置变量**（不硬编码），上游模型涨价后台一键调价 + 公告

### 4.2 定价推导（Q14 + D4）

**口径**：实际 token/调用成本占售价 30%（售价 = 成本 ÷ 30%）。

**模型成本（2026-08-06 查证，DeepSeek 价格有变动风险）**：
| 模型 | 用途 | 计价 |
|:--|:--|:--|
| deepseek-v4-flash | 文本 | 输入 1 元/M token，输出 2 元/M token（**峰谷翻倍已执行 + 预告大涨**） |
| Seedream 5.0 | 生图 | 0.22-0.3 元/张（仅成功计费） |
| MiniMax H3 | 生视频 | 0.50 元/秒（768P）/ 0.80 元/秒（2K） |
| Seedance 2.0 | 生视频 | ≈1 元/秒（720p，按输出 token 计费） |

## 5. 知识体系（核心护城河）

### 5.1 知识沉淀飞轮（Q13 + D5）

**延用灵犀设计之初方案**（讨论纪要 2.5/2.6/3.1/3.2），适配"租户×场景"：

```
客户使用 AI 干活
    ↓（记忆沉淀）
租户×场景 bank（informate-tenant_<租户>_<场景>）
    ↓（聚合脚本，v2.0 后自动化）
提取 → 去重 → 脱敏 → 人工审核（Obsidian）→ 标记二级行业
    ↓
行业 bank（informate-industry_<一级行业>，条目带 sub_industry）
    ↓
同行业其他客户加载行业知识库 → 获得更好的 AI 服务
```

**D5 调整：人工知识先行**——MVP 阶段只做租户层记忆；行业层/通用层靠 Obsidian **人工种子知识**（评审采纳：量级加大至**每行业 100 术语 / 50 FAQ / 20 SOP / 20 案例 / 10 模板**，需覆盖二级行业；由**指定知识编辑角色**生产，可外包行业顾问）；**聚合脚本（自动飞轮）放到 v2.0**（触发条件量化：单行业 ≥10 租户 + 审核通过率 ≥X% + opt-in 覆盖率 ≥Y%）。

**数据所有权**：客户业务数据归客户；脱敏后的行业知识（术语/场景/模板）归平台。

**两阶段商业模型**：第一阶段低价跑数据（积累行业知识）→ 第二阶段提价变现（行业高级版/垂类 agent）。

### 5.2 知识库结构（Q16 + Q25）

| 层 | 粒度 | 内容 | 谁写 |
|:--|:--|:--|:--|
| 通用层 | informate-common | 平台级 FAQ/话术/SOP | 平台 |
| 行业层 | informate-industry_<一级行业> | 行业术语/FAQ/话术/法规库，条目带 sub_industry（二级行业） | **人工种子 + 飞轮聚合（人工审核后）** |
| 租户层 | informate-tenant_<租户>_<场景> | 租户私有知识 | 租户自己的 agent |

**二级行业检索逻辑（评审采纳，硬编码优先级 P1-P4，不用向量加权）**：
```
P1: 租户私有 bank（精确匹配二级行业）
P2: 行业 bank 中 sub_industry = 租户二级行业（如植发）
P3: 行业 bank 中 sub_industry = 通用/空（医美一级通用）
P4: 通用 bank
```
Hindsight bank 检索本质是**结构化分层读取**，不是语义搜索混合排序；条目不均时（植发只有 2 条）靠 P3 兜底。

**调研结论**（Q16）：不引入重型平台（Dify/RAGFlow/FastGPT 都不装）——底座 = Hindsight bank 体系；借鉴 RAGFlow 文档解析分层、MaxKB 管理界面、mem0 记忆提取生命周期；自研知识 schema（术语/FAQ/话术/SOP/法规库 + sub_industry 字段）+ 聚合脚本 + 管理 API。

### 5.3 Obsidian 人工层（Q17 + Q19）

- **Obsidian = 人工知识资产层**（`~/Desktop/Informate KB/`，git）；Hindsight = 机器记忆层
- **双向同步**：Hindsight 聚合 → flywheel/ 待审阅草稿 → 人工审阅编辑 → industries/ 权威版 → 回灌 Hindsight 行业 bank
- **强制人工审核（Q19）**：脱敏脚本提取的知识仅作 Draft 进 flywheel/，**未经人工批准严禁回灌行业 bank**；flywheel 区实现**差异高亮**（一眼看出脱敏掉的品牌词 vs 提炼的行业 SOP）
- **三角色**：飞轮人工质检站 / 行业知识资产库 / 交付物来源
- **红线**：租户私有数据绝不进 Obsidian

### 5.4 合规（Q19，监管硬约束）

2026 年 AI 监管收紧（DeepSeek 情报）：
1. **Opt-in 客户许可**：服务协议明示或"加入知识共享计划享积分打折"显式开关
2. **AI 生成内容标识**：图片/视频加水印或元数据标记（生成式 AI 国标 + 清朗专项行动红线）
3. **大模型备案**：使用 deepseek/Seedream/H3 提供服务需评估算法/大模型备案义务
4. **数据合规**：客户输入数据用于训练的需持续提示并显著告知关闭方式
5. **商业秘密保护**：2026 年 6 月《商业秘密保护规定》首次将"数据""算法"纳入保护

**优势**：M1 合规引擎（违禁词 + 4 行业规则包 + LLM fallback + 自动修正）可复用，是差异化资产。

### 5.5 护城河（竞品调研验证）

**护城河假设**：行业 × 场景的知识沉淀飞轮 → 具有行业场景知识的垂类 agent（可细化到二级行业：医美-植发工作助手）。

**竞品调研结论**（`artifacts/01_strategy/竞品调研报告.md`）：
1. 护城河**成立但比想象中窄**——"跨客户脱敏聚合 → 行业×场景知识库 → 回灌垂类 agent"闭环**目前无竞品做透**（Coze 记忆库不跨客户聚合；小多 AI 只做电商客服单场景）
2. **最大竞品 Coze 企业版**（490 元/月起 + 积分 + 记忆库），但它是"搭建型"平台——Informate 差异化在"**不用搭的 AI 工作台**"
3. **护城河本质是运营不是技术**——行业运营深度 + 客户关系 + 数据积累 + 合规能力
4. **时间窗口短**（DeepSeek）：大厂 6 个月内可能推出行业场景包 + 跨客户知识聚合 → **速度 + 深度 > 平台功能**
5. **加厚方向**：行业运营深度 / 合规能力产品化 / 交付服务标准化（开通即懂行）/ 垂类 agent 第二阶段单独售卖
