## 1. 架构与端口一览

### 1.1 组件拓扑

```
┌──────────────┐   /api (proxy)   ┌──────────────────┐
│  前端        │ ───────────────▶ │  后端 backend    │
│  React+Vite  │ :5173            │  Node+TS+Fastify │ :8080
│  (三栏工作台) │ ◀─────────────── │  +SQLite         │
└──────────────┘    JSON/SSE      └────────┬─────────┘
                                           │
                     ┌─────────────────────┼─────────────────────┐
                     ▼                     ▼                     ▼
          ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
          │ 合规服务         │  │ Hermes api_server│  │ 火山方舟 Seedream │
          │ Python FastAPI   │  │ 真实对话(可选)    │  │ 真实生图(待接入) │
          │ :9100            │  │ :8647 (外部进程)  │  │ 外部 API          │
          └──────────────────┘  └──────────────────┘  └──────────────────┘

  任务队列：REDIS_URL 已配置且安装 bullmq → Redis+BullMQ；否则内存 FIFO（MVP 单机形态）
  记忆：Hindsight :9177（可选外部服务，不可用时记日志降级）
```

### 1.2 端口一览

| 端口 | 服务 | 目录 | 开发启动 | 生产启动 |
|:--|:--|:--|:--|:--|
| **8080** | 后端 API（Fastify + SQLite） | `backend/` | `npm run dev`（tsx watch） | `npm run build && npm run start`（node dist/index.js） |
| **9100** | 合规服务（FastAPI） | `services/compliance/` | `.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 9100` | 同上（uvicorn 由 pm2 托管） |
| **5173** | 前端开发服务器（Vite，`/api` 代理到 8080） | `frontend/` | `npm run dev` | **不启动**，见下 |
| 8647 | Hermes api_server（可选，真实对话用） | 外部 | 外部启动 | 外部启动 |
| 9177 | Hindsight（可选，记忆服务） | 外部 | 外部启动 | 外部启动 |
| 6379 | Redis（可选，BullMQ 队列） | 外部 | 外部启动 | 外部启动 |

### 1.3 生产环境前端托管（重要）

**开发**：Vite dev server（:5173），`/api` 请求由 vite proxy 转发到 :8080。
**生产**：**不跑 Vite dev server**。构建静态产物后用任意静态服务器托管：

```bash
cd frontend
npm run build        # 产物输出到 frontend/dist/
# 托管 dist/（任选其一）：
npx serve dist -l 80                     # 简单静态托管
# 或 nginx 配置示例：
#   server {
#     listen 80;
#     root /opt/informate/frontend/dist;
#     location /api/ { proxy_pass http://127.0.0.1:8080; }   # 转发后端
#     location / { try_files $uri /index.html; }             # SPA 路由回退
#   }
```

> 注意：静态托管时 `/api` 必须反向代理到 :8080（生产不再走 Vite proxy）。SSE（chat 流式）经 nginx 需关闭缓冲：`proxy_buffering off;`，否则对话流式输出会卡顿。

### 3.3 备份 / 恢复

> P1-15 整改：备份**仅保留 sqlite3 `.backup` 在线备份**一种方式（原子、自动合并 WAL）。~~直接 `cp` 三个文件~~（db/-wal/-shm 非原子，可能拷到未合并 WAL）不再推荐。

**备份 = sqlite3 在线备份（不停服，原子）**：

```bash
cd ~/Desktop/Informate\ Project/backend
sqlite3 data/informate.db ".backup '/backup/informate_$(date +%Y%m%d_%H%M%S).db'"
```

> 建议备份频率：每日一次 + 每次发版前一次；备份保留最近 7 份。备份后可校验完整性：`sqlite3 /backup/informate_*.db 'PRAGMA integrity_check;'`（期望 `ok`）。

**恢复 = 停服替换 + 完整性校验 + 重启**：

```bash
# 1) 停掉 backend（pm2 stop informate-backend 或 kill，见第 4 章）
# 2) 替换数据文件（连同 -wal/-shm 一起删掉旧的，防止脏 WAL 覆盖新数据）
cd ~/Desktop/Informate\ Project/backend
rm -f data/informate.db data/informate.db-wal data/informate.db-shm
cp /backup/informate_YYYYMMDD_HHMMSS.db data/informate.db
# 3) 完整性校验（期望输出 ok；非 ok 立即停止，换更早的备份）
sqlite3 data/informate.db 'PRAGMA integrity_check;'
# 4) 重启 backend，验证登录与 /health
```

### 4.2 生产环境（pm2 建议）

```bash
npm i -g pm2

# 首次构建（backend TS 编译 + frontend 静态产物）
cd ~/Desktop/Informate\ Project/backend && npm run build && cd ..

# 启动（在项目根目录执行，pm2 配置文件见下方 ecosystem.config.js）

```

**ecosystem.config.js 示例**（放项目根目录）：

```js
module.exports = {
  apps: [
    {
      name: 'informate-backend',
      cwd: '/Users/zhangyihui/Desktop/Informate Project/backend',
      script: 'dist/index.js',          // npm run build 产物
      interpreter: 'node',
      instances: 1,                      // 单实例（better-sqlite3 单进程，勿开 cluster）
      autorestart: true,
      max_restarts: 10,
      env: {
        NODE_ENV: 'production',
        PORT: '8080',
        DB_PATH: 'data/informate.db',
        JWT_SECRET: '<生产强随机密钥>',   // 必须注入！见第 5 章
        ARTIFACTS_DIR: 'data/artifacts',
        // SEEDREAM_MODE: 'mock',        // P0-3：真实生图未接入，试点期保持 mock
        // VOLC_ARK_API_KEY: '<火山方舟Key>',   // P0-3：真实接入待实现（试点前置），暂勿设置
        // REDIS_URL: 'redis://localhost:6379',
        HERMES_MODE: 'real',             // 真实对话
        HERMES_API_BASE: 'http://127.0.0.1:8647',
        HERMES_API_KEY: '<api_server Key>',
        // HINDSIGHT_API_BASE: 'http://localhost:9177',
        COMPLIANCE_BASE_URL: 'http://127.0.0.1:9100',
      },
      out_file: '/tmp/informate_backend.log',
      error_file: '/tmp/informate_backend_err.log',
      merge_logs: true,
    },
    {
      name: 'informate-compliance',
      cwd: '/Users/zhangyihui/Desktop/Informate Project/services/compliance',
      script: '.venv/bin/python',
      args: '-m uvicorn main:app --host 127.0.0.1 --port 9100',
      autorestart: true,
      out_file: '/tmp/informate_compliance.log',
      error_file: '/tmp/informate_compliance_err.log',
```

### 4.3 停止 / 重启 / 状态

```bash
pm2 stop informate-backend            # 停止
pm2 restart informate-backend         # 重启（加载新代码/新环境变量）
pm2 reload informate-backend          # 零停机重载（单实例下同 restart）
pm2 status                            # 查看所有进程状态
pm2 logs informate-backend            # 实时日志
pm2 startup && pm2 save               # 开机自启
```

后端支持优雅退出：SIGINT/SIGTERM 时先 `app.close()` 再退出，pm2 的 stop/restart 默认发 SIGINT，无需额外配置。

## 5. 环境变量清单

后端读取 `.env`（`backend/` 下，模板见 `backend/.env.example`）与进程环境变量；进程环境变量优先。

| 变量 | 默认值 | 说明 |
|:--|:--|:--|
| `PORT` | `8080` | 后端监听端口 |
| `DB_PATH` | `data/informate.db`（相对 backend/） | SQLite 数据文件路径；测试用 `:memory:` |
| `JWT_SECRET` | 开发 `informate-dev-secret-change-me` | JWT 签名密钥。**生产必须注入强随机值**：`NODE_ENV=production` 且未设置时直接拒绝启动；开发模式会打印警告 |
| `JWT_EXPIRES_IN` | `7d` | JWT 有效期（可选） |
| `ARTIFACTS_DIR` | `data/artifacts`（相对 backend/） | 生图产物落盘目录 |
| `SEEDREAM_MODE` | 未设置 | `mock` 强制占位图模式（P0-3：真实接入未实现，生产/试点保持 `mock`） |
| `VOLC_ARK_API_KEY` | 空 | 火山方舟 Seedream API Key。⚠️ **真实接入未实现**（`generateReal()` 抛 `SEEDREAM_REAL_NOT_CONFIGURED`），现阶段**请勿设置**；真实接入列为试点前置任务（P0-3） |
| `REDIS_URL` | 空 | 如 `redis://localhost:6379`。设置且已 `npm i bullmq` → Redis+BullMQ 队列；否则内存 FIFO（重启丢排队任务） |
| `HERMES_MODE` | `mock` | `mock`=本地占位流式回复（联调）；`real`=转发真实 Hermes api_server（上线必须 `real`） |
| `HERMES_API_BASE`（部署任务书又称 HERMES_BASE_URL，代码实际读取前者） | `http://127.0.0.1:8647` | Hermes api_server 地址；`HERMES_MODE=real` 时生效 |
| `HERMES_API_KEY` | `spike-userid-test-key` | api_server 调用密钥；`HERMES_MODE=real` 时使用 |
| `HINDSIGHT_API_BASE` | `http://localhost:9177` | Hindsight 记忆服务地址；不可用时记忆写入降级（记日志） |
| `COMPLIANCE_BASE_URL` | `http://127.0.0.1:9100` | 合规服务地址；不可用时 Chat/生图 fail-closed 503（医美红线） |
| `PUBLISH_REVIEW_HINT` | 内置缺省文案 | 合规服务（compliance，非 backend）环境变量：医美文案发布审查提示，启动覆盖 `GET /hint` 返回的缺省文案（运行时可用 `PUT /hint` 持久化到 `data/publish_hint.json`） |
| `NODE_ENV` | 未设置 | 设 `production` 强制 JWT_SECRET 校验（pm2 env 中设置） |

生产必配 3 项：`NODE_ENV=production`、`JWT_SECRET`（强随机）、`HERMES_MODE=real` + `HERMES_API_BASE` + `HERMES_API_KEY`（真实对话）。生图：P0-3 降级——真实接入待实现，试点期保持 mock 演示模式（**勿设 `VOLC_ARK_API_KEY`**），真实接入列为试点前置任务。

生成强随机密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 6.3 常见问题速查表

| 症状 | 可能原因 | 处理 |
|:--|:--|:--|
| 启动 backend 报 `EADDRINUSE` / 端口被占 | 8080 被旧实例/其他进程占用 | `lsof -i :8080` 找到 PID → `kill <PID>` 后重启 |
| 登录报 `UNAUTHORIZED 账号或密码错误` | 旧 backend 实例持空库连接（早于 migrate 启动） | `lsof -i :8080` 杀掉旧 PID → 重启 backend（DB 文件本身正常，勿删库） |
| `SQLITE_BUSY` / DB 锁错误 | 多进程同时写同一个 db 文件（如误开 cluster 多实例） | 确认 backend 单实例运行；better-sqlite3 单进程 + WAL，勿 `instances > 1` |
| 启动日志 `开发模式使用默认 JWT_SECRET` 警告 | 生产未注入 JWT_SECRET（或 NODE_ENV 未设 production） | 注入强随机 `JWT_SECRET` + `NODE_ENV=production`；否则任何人都可用已知默认密钥签发 admin token |
| Chat/生图返回 `503`（合规服务不可用） | `COMPLIANCE_BASE_URL` 指向的 :9100 没起来 | 启动 compliance（`bash scripts/dev_start.sh` 或 pm2）；确认 `curl :9100/health` 通过。合规 fail-closed 是医美红线设计 |
| 生图任务失败报 `SEEDREAM_REAL_NOT_CONFIGURED` | 设置了 `VOLC_ARK_API_KEY`，但真实接入未实现（P0-3） | 现阶段**不要设置** `VOLC_ARK_API_KEY`；保持 mock 演示模式，真实接入列为试点前置任务 |
| 生图一直返回占位图 | 当前即为 mock 演示模式（P0-3 降级，预期行为） | 属预期：真实接入待实现；试点按「mock 演示链路」验收（登录→生图→产物落盘） |
| 对话是占位回复 | `HERMES_MODE=mock` 或 api_server 未启动 | 设 `HERMES_MODE=real`；确认 `curl http://127.0.0.1:8647/health` 可达、Key 正确 |
| `REDIS_URL 已设置但未安装 bullmq` 警告 | 配了 Redis 但没装 bullmq | `cd backend && npm i bullmq`（不装则回落内存 FIFO，功能可用但重启丢排队任务） |
| 前端页面空白/接口 404 | 静态托管未代理 `/api`，或 SPA 路由未回退 | nginx 配 `location /api/ { proxy_pass http://127.0.0.1:8080; }` + `try_files $uri /index.html` |
| SSE 流式对话卡顿/不实时 | 反向代理缓冲了 SSE | nginx 加 `proxy_buffering off;` |


## 9. 零号客户试点准备清单（医美）

目标：零号客户（医美机构）从开户到打样可复制，**打样指标：周活 ≥ 60% / 任务完成率 ≥ 70% / 续费意向 ≥ 80%**。

### 9.1 流程（顺序执行）

1. **开户**：管理后台创建客户租户（或复用种子租户流程）→ 分配行业=医美、场景=行业工作助手 + 生成图片
2. **试用**：开通试用额度（默认 `trial` 状态）→ 引导客户走一遍「工作助手会话 → 生图 → 充值」全链路，确认无 503/占位图
3. **充值**：客户确认效果后首次充值（档位 100=1100 / 500=6000 / 2000=25000 积分）；部署费 ¥500/场景一次性（首单免）
4. **员工账号**：为客户创建员工账号（employee 角色，密码按客户规范设置并交付），按需分配权限
5. **培训 15 分钟**：现场培训标准动作——
   - 打开工作台 → 新建会话（消耗 15 积分/会话）
   - 输入医美场景问题（如话术/案例/合规提醒），演示 SSE 流式回复与 20 轮内免费、超轮计费
   - 演示生图（提示词 + 合规前置检查），下载产物
   - 演示充值流程与积分余额查看
6. **打样验收（两周）**：每周统计——
   - **周活**：活跃员工数 / 员工总数 ≥ 60%
   - **完成率**：完成会话（到达 round_complete / 产出落库）/ 发起会话 ≥ 70%
   - **续费意向**：试点末调研（充值续费意向）≥ 80%
   - 未达标 → 复盘培训覆盖、场景包贴合度、定价感知，调整后进入下一轮试点
