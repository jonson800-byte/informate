## 1. 项目概述

**Informate = B 端 AI 能力平台**：企业级场景化 Chat 工作台（三栏布局：左场景列表 / 中对话 / 右产出物面板），让企业用 AI 干活。零号客户行业=医疗美容，MVP 范围=行业工作助手 + 生成图片。

**核心商业闭环**：企业开户 → 充值得积分（1 元=10 积分）→ Chat 场景消耗积分 → 产出物自动展示右侧面板 → 用完再充。

**技术本质**：场景 = Hermes Agent profile（模型+角色+技能+工作流+知识库）的动态实例；多租户记忆 = Hindsight bank 隔离（`informate-tenant-{user}-{profile}`）；行业知识沉淀飞轮 = 护城河（跨客户脱敏聚合 → 行业×场景知识库 → 回灌垂类 Agent）。

**当前状态**：MVP 开发完成（5 个批次全部通过 Codex RedTeam 验收），本地部署可用（mock 模型模式），腾讯云部署与真实模型接入为下一阶段。

### 1.1 关键决策基线（Q1-Q29 + D1-D5 全部闭环）

| 维度 | 决策 |
|:--|:--|
| 商业模式 | 部署费 ¥500/场景/一次性 + 积分消耗；首单免部署费 |
| 工作助手定价 | **15 积分/会话**（含 20 轮，超轮 1 积分/轮，50 轮上限，第 51 轮拦截）——2026-08-17 DeepSeek 峰谷涨价后定稿 |
| 生图定价 | 对外 20 / 实扣 15 积分（Seedream 5.0） |
| 生视频 | 标准档 200 / 品质档 400 积分（H3/Seedance，MVP 降级增购项） |
| 租户状态机 | trial（20 次试用）→ active（充值即转）→ paused（欠费冻结）→ expired |
| 计费模式 | 按场景单价计费（非 token）；冻结/结算/解冻两阶段；失败退积分 |

## 2. 系统架构

### 2.1 拓扑

```
浏览器 (React SPA, :5173 开发 / nginx 静态托管 dist/)
   │ proxy /api
   ▼
Node.js API (Fastify :8080)
   ├── 路由层：auth / auth_tenant / scenarios / workspace / chat / imagegen /
   │           credit / users / admin / admin_credit / health
   ├── 服务层：credit（积分账本）/ hermesClient（AI 对话）/ memory（Hindsight 记忆）/
   │           seedream（生图）/ taskQueue（任务队列）
   ├── 中间件：authenticate（JWT）/ requireRole（owner/employee/admin）
   │
   ├──▶ Hermes api_server (:8647 生产 / mock 本地) —— 场景 Agent 推理
   │       └──▶ Hindsight (:9177) —— 租户×场景 bank 记忆读写
   ├──▶ Seedream 5.0（火山方舟，mock/real）
   ├──▶ 合规引擎 (Python FastAPI :9100) —— fail-closed
   └──▶ SQLite (WAL, 10 表 + 迁移记录)
```

### 2.2 数据流（核心业务）

**Chat 会话**：
```
POST /chat/messages → 归属校验（401/404/403）→ 轮次校验（第 51 轮 429）
→ 输入侧合规（9100，blocked→400 含法规依据）→ 记忆 recall（租户 bank P1 → 行业 P2 → 通用 P3）
→ Hermes 流式（SSE：delta/round_hint/round_complete/error）→ 输出侧合规（同引擎，fail-closed）
→ 消息落库 + 轮次计费（第 21 轮起 1 积分/轮，同事务幂等）→ 异步 writeMemory
```

**生图**：
```
POST /credit/image-tasks（冻结 15）→ POST /image-tasks/:id/execute（前置合规，blocked→解冻）
→ 入队（内存 FIFO/BullMQ）→ worker 处理（pending→processing）→ Seedream 生成
→ 成功：settle + artifact=success + url 落盘；失败：release 原子退分 + fail_reason
→ GET /image-tasks/:id（前端轮询）；GET /artifacts/:id/download（文件流）
```

### 2.3 关键设计决策与权衡

| 决策 | 权衡 |
|:--|:--|
| 按场景单价计费（非 token） | 客户可预期；模型涨价风险由平台承担（触发阈值调价机制兜底） |
| 冻结/结算/解冻两阶段 | 防止任务失败后积分丢失；冻结即扣（余额实时减少） |
| 后端直调 Hindsight（Q30） | 绕开 Hermes provider 配置黑盒；记忆隔离完全由平台掌控 |
| 合规 fail-closed | 服务不可用 → 503 拒绝（不放行未审核内容）——以可用性换合规确定性 |
| SQLite + better-sqlite3 | 单机部署极简；同步事务天然串行（无并发写竞争）；>20 并发需 busy_timeout |
| 无 Redis 内存队列 | 开发/试点零依赖；生产切 BullMQ（代码已预留，懒加载） |

## 4. 积分状态机（核心计费逻辑）

### 4.1 会话级（工作助手）

```
POST /conversations 创建 ──▶ frozen 10→15（创建即冻结，credit_txn: freeze, ref=conversation）
   │
   ├── 第 1-20 轮：不追加扣费（含在冻结内）
   ├── 第 21-50 轮：每轮增量冻结+结算 1 积分（round_extra）
   ├── 第 51 轮：429 ROUND_LIMIT_EXCEEDED，提示新开对话（防套利）
   │
   ├── 会话结束/扫描结算：按实际轮数 settle；未使用会话（N 分钟无消息，默认 30）全额解冻
   └── 兜底扫描（scanExpiredFreezes）：活跃会话跳过（禁止按时长解冻）；
       成功任务补结算；失败任务补退分；生图超时（默认 30 分钟）原子解冻
```

### 4.2 生图任务级（两阶段）

```
冻结 15（unit=image，与会话费独立）→ 入队 → 生成成功 settle（余额不变，冻结时已扣）
→ 失败/超时 release 原子退分（退回差额 Σfreeze−Σunfreeze−Σsettle，防冻结卡死）
→ 已退分任务重放：不重复冻结、不重复扣费（幂等）
```

### 4.3 幂等机制

- `credit_txn.idempotency_key` UNIQUE + 按 (ref_type, ref_id) 查重
- 充值重放不重复到账；会话重放不重复冻结；轮次重放不重复扣费（全部有测试覆盖 T5.7）
- 消息落库与扣费同事务（防崩溃窗口扣费成功但消息丢失）

### 4.4 欠费冻结（FR-605）

```
active 且 balance < minFreeze(15) → 租户 paused（整页冻结，新会话/生图拦截）
paused 且 balance >= minFreeze → 充值即时恢复 active（AC-605，1 分钟生效）
试用（trial）：查次数（20 次会话）不查余额、不冻结、不走冻结页
余额 < 30 积分：琥珀色预警（UI）
```

### 4.5 定价依据（2026-08-17 DeepSeek 峰谷涨价后重算）

| 项 | 数值 |
|:--|:--|
| flash 高峰价（9-12/14-18 点） | 输入未命中 3.0 元/M、输出 9.0 元/M（输出涨 4.5x） |
| B 端客户主力时段 | 高峰时段（B 端工作时间）→ 按高峰价核算 |
| 中性假设会话成本 | 20 轮 × (3.0×2K + 9.0×1.5K)/1e6 ≈ 0.39 元 |
| **15 积分售价毛利** | **76.3%**（10 积分仅 64.5% 擦边，悲观假设 38.7% 会亏） |
| 超轮毛利 | 82%（利润点） |
| 调价触发阈值 | 单会话成本 ≥ 0.45 元（毛利 70% 临界）→ 管理后台调价（SQL/API 即改即生效） |

## 5. Hermes / Hindsight 集成（多租户 AI 核心）

### 5.1 架构（Q30 方案 B）

```
Node.js 后端 ──HTTP──▶ Hindsight REST API (:9177)
  ├── 写入：POST /banks/informate-tenant-{租户}-{场景}/memories（Q30，租户×场景独立 bank）
  ├── 检索：POST .../memories/recall（P1 租户私有 → P2 行业 → P3 通用，硬编码优先级）
  └── 行业知识库：informate-industry_{行业} 只读（平台写入，同行业租户共享）

Node.js 后端 ──SSE──▶ Hermes api_server (:8647)
  ├── 请求头：X-Hermes-User-Id（租户隔离通道，源码级补丁）、X-Hermes-Session-Id（会话连续性）、Bearer token
  └── 角色/技能/知识注入：由平台按场景包构建（profile 模板化）
```

### 5.2 已验证的关键事实（防止评估者重跑实验）

- **bank_id_template 机制**：`plugins/memory/hindsight/__init__.py:1072` 解析占位符 `{user}/{profile}` → 动态 bank；配置来源实测为 `$HERMES_HOME/hindsight/config.json`（**不读 config.yaml memory 段**）
- **X-Hermes-Session-Key 不能隔离租户**：SPIKE 实测两个 session 检索均返回同一完整列表（`紫罗兰、骆驼、青苹果、红玫瑰`）→ 会话键只保连续性、不作用户级隔离
- **api_server 隔离方案**（已落地补丁）：`api_server.py` 补 `X-Hermes-User-Id` 头 → `_bind_api_server_session` 注入 `set_session_vars(user_id=...)`（约 10-20 行，补丁脚本 `scripts/hermes_patch_x_hermes_user_id.patch`）
- **Hermes 记忆默认行为**：agent 自动 retain 写默认 bank（hermes）→ 被平台忽略、无业务影响（平台只认自己直调的租户 bank）

### 5.3 记忆层设计（backend/src/services/memory.ts）

- `writeMemory(tenantId, scenarioId, content)`：写租户×场景 bank（中文 bank 名 URL encode）
- `recallMemory(tenantId)`：P1 租户私有 bank 优先
- `industryRecall(industry, subIndustry)`：行业 bank → 子行业 → 通用回退（P2/P3）
- 召回结果注入 system prompt（行业工作助手人设 + 知识叠加层，Q28）

## 6. 合规引擎（Python FastAPI :9100）

### 6.1 规则体系

| 规则包 | 模式 | 示例 |
|:--|:--|:--|
| general-1.0 | 修正（替换违禁词） | 最佳/第一/顶级/根治/100% → 建议替换词 |
| medical-1.1 | 拦截（含法规依据） | 前后对比承诺/治愈率/变相广告/贬低同行/无痛无痕 |

**技术**：纯 Python AC 自动机 + 正则引擎（0 外部依赖），语境敏感（第一条/第一次不误伤）、重叠去重（全国第一 不重复触发 第一）、拦截优先级（命中红线整条拦截）。

### 6.2 接入点（全链路 fail-closed）

- Chat 输入侧：blocked → 400 COMPLIANCE_BLOCKED（含法规依据）
- **Chat 输出侧**（batchE P0 修复 + 2026-08-16 P0-2 分段闸门）：流式输出改为「服务端按句缓冲 → 增量合规 → 通过才转发」，**被 blocked 的文本块绝不到达浏览器**；流结束后完整回复终检（控制落库/结算）；合规服务不可用 → 停止转发 + SSE error（拒绝放行）
- 生图前置：违禁 prompt 不入队并原子解冻（不产生扣费）
- FR-209：生成文案附「需人工审核+《医疗广告审查证明》方可投放」提示（GET /hint 可配置）
